# 幕间 Interlude

**简体中文** | [English](README.en.md)

**你写一句剧情，剩下的交给引擎。**

它会把你写的东西拆开、搭起场景、派发给场上每个角色，让他们**挨个**反应，再按时间顺序把这一幕接进故事线。

![主界面](docs/images/01-board.jpg)

---

## 它和酒馆（SillyTavern）有什么不一样

两者都是自托管的角色扮演前端，都用自己的 API Key，都能导入自己喜欢的模型。区别在于**「谁来决定该发生什么」**。

酒馆把决定权交给你：你写一条消息，AI 回一条，你看着不对就改提示词、调采样参数、上正则。它是一台**非常好用的单角色对话机器**。

幕间想做的事不一样：**你只负责写剧情，引擎负责调度。** 你把一段素材丢进去，它自己判断这段里哪些是台词、哪些是动作、哪些是场景、哪些是没说出口的；判断谁在场；再由一个「局面」决定这一轮谁先动、世界会怎么变；然后让角色**按顺序挨个**反应 —— 后开口的人看得见先开口的人刚说了什么。

| | 酒馆 | 幕间 |
|---|---|---|
| **一次输入** | 一条消息 = 一次生成 | 一段素材 = 一整轮，场上所有角色**按顺序**挨个反应，后来的人听得见前面的人 |
| **你说的话** | 就是消息本身 | 先被拆解成片段，你说出口的话会被**锁定**，AI 一字不能改 |
| **心理描写** | 直接写出来，所有人都看得见 | 不外传。结合你写的人设，只把「看得见的痕迹」给对方 |
| **信息差** | 上下文全员共享 | 每个角色一份**私有上下文**，含一份「你确定不知道的事」 |
| **配角** | 要自己建卡 | 自动生成；再出场时**复用**同一张卡，人设不漂 |
| **看到了什么** | 只能看最终输出 | 点开任意角色，能看到它这一轮**实际拿到了什么** |
| **改坏了怎么办** | 删消息重来 | 任意一步可编辑，**只重跑受影响的那条分支** |
| **剧情推进** | 你不写就停在那里 | 有一个独立的「**局面**」（这一场戏的导演）在推：它决定世界怎么变，也决定谁先动 |
| **谁来导演** | 你。你写的每个字都要自己扛起整场戏 | 你只提出「点」，**导演**负责安排这一轮还发生什么、谁做什么、往哪走 |
| **结构** | 一条聊天记录 | 「对话」（可切换的故事线）＋ 线性轮次 |
| **设置项** | 一大堆 sampler、预设、正则 | 只有三个开关 |

还有一条最不一样的：**你在幕间里说的话，AI 改不了。** 酒馆里你打的内容通常只是"给 AI 看的输入"，而在幕间里它是一份要照着演的剧本——你说出口的台词会原样出现在舞台上，AI 只能补动作、微表情和它自己的话。

### 三层：你是提出「点」的人，导演才是导演

这是两者在"手感"上差别最大的地方。

酒馆里，剧情是**你一句、AI 一句**推着走的：你不发消息，故事就停在那儿。你实际上得同时扮演编剧、导演和主角，累且容易僵。

幕间把这件事拆成三层：

- **你**只负责提出「点」—— 一句话、一个动作、一个念头。但这个点**必须被采纳**：那是这一轮一定会发生的事，没人能把它忽略掉。除此之外你不用操心。
- **导演**（引擎里那个不代表任何角色的行动者）拿着**充分的自主性**：这一轮还发生什么、谁做什么、节奏多快、这一幕往哪走，都是它的。用户没写的东西不是"不该发生"，而是**该由它来安排**。它每轮都问自己一件事：**如果所有人都不作为，接下来会发生什么？** 然后让世界往前走一步：外面的动静又近了一点、火塘塌了一角、对方的耐心少了一分。
- **角色**既要演，也可以推。导演给出的是**骨架**，角色按自己的人设把血肉长出来 —— 而且他**完全可以推动剧情**：想走就走、想动手就动手、想问就把话问出来。他的行动会变成既成事实进入下一轮，导演必须接着处理——所以放他自己走，这出戏不会散。

万一还是僵住了（你的人设就是不会主动的人，角色也各有各的理由等着），导演会**点名**：挑一个最该动的人，直接告诉他这一轮做了什么——「再等下去就来不及了；他动了 —— 抢在那扇门合上之前，一把把它按住了」。导演通读台本，和演员有同样的权限，只是**只有僵局时他才说**。指令到剧情为止：怎么说、什么表情、什么节奏，仍然是那个角色自己演。**你扮演的角色永远不在点名范围内**——你写什么就是什么，没人能替你动。

引擎里也没有"每个角色每轮必须开口"这种规则。打起来的时候，他们的主战场是动作，不是台词。

而且**角色的反应不必是对着你的**。局面发生的事（外面的动静、正在塌下来的东西）和你写的言行排在**同一条时间线**上，不是背景板。所以该去处理那件事的时候就去处理，可以整轮不跟你说一个字 —— 他不会回头指挥你，因为要回应的是局势，不是你。导演还会在需要的时候**明确拦住他**：「这一轮不要跟用户交互。」

**冲突也不会永远悬着。** 同一场对峙拖到第四轮还在原地加码，那不是紧张，那是卡住了 —— 导演手里有一条独立的**收场**职责：连着几轮都在升级时，它得让这一幕落地（分出结果、有人退场、有外力打断、代价付清）。已经结束的事它不会再翻出来。

**酒馆更适合**：想精细控制每一次生成、依赖世界书（Lorebook）和正则、习惯自己调教提示词。
**幕间更适合**：不想管这些，只想写剧情，然后看一群人自己动起来。

## 心理描写不会被别人读到，但它会「外化」

这是幕间最核心的一条规则。

你写：

```
我其实。。。。（我有点犹豫）。。。。也没那么想回家。。。。
```

引擎**不会**把「我有点犹豫」发给任何角色。它结合你的人设判断：这种犹豫在你身上会留下什么**看得见的痕迹**——

> 话说了一半停下来，手指在伞柄上蹭了一下

角色拿到的是这句话，而不是你的心里话。而且这行字还带着两个数：

- **可读性 35%** — 对方把这条线索读成「他在犹豫」的概率
- **泄漏 50%** — 你这个人在人设上有多藏不住事

人设里写了"城府很深、习惯控制表情"，泄漏就会压到 10~20%；写了"藏不住事"，就会到 70~80%。如果人设就是能完全压住，它也可以**一点都不露**。

## 点开任意角色，看它到底收到了什么

这是幕间区别于普通角色扮演的地方：**没有黑箱**。

点角色卡上的「它收到了什么」，你会看到它这一轮拿到的全部信息，按时间顺序排列：

```
1. 你说：「我其实。。。。」
2. 你注意到「我」：话说了一半停下来，手指在伞柄上蹭了一下
3. 你说：「。。。。也没那么想回家。。。。」
4. 你看我
5. 你说：「我可以。。。。跟你待一会吗。」
```

**注意这是「依次发生」的，不是「并列发生」的。** 你说一句、停一下、再说一句——角色感知到的就是这个顺序，而不是一张"他说了什么 / 他做了什么"的分类清单。

而且**这是他自己视角的说法**。你写「我抬头看了你一眼」，被你看的那个人读到的是「他抬头看了我一眼」，旁边的第三个人读到的是「他抬头看了林砚一眼」。你写的「我」在别人眼里从来不是「我」——那会让他们以为是自己干的。台词是唯一的例外：引号里是你写的原话，一个字都不改，只换说话人的称呼。

再往下还有：**他亲身经历的往事**（一轮一段，从第 1 轮一路累加，包含他自己当时说过做过什么、当时在想什么），以及一份写明白的「**他确定不知道的事**」。

往事是**逐轮累加、永不重写**的：第 5 轮发出去的东西，就是第 4 轮发出去的东西再往后接一段。这样同一个角色跨轮次的提示词前缀能命中缓存，而且他不会忘掉三轮前说过的那句话 —— 这也是它和「只带最近几句话」的做法最大的区别。

## 角色会记得上一轮

同一个角色再次出场，他会带着前面几轮的记忆上场——他听到的、他说过的、他当时心里想的。所以他能跟你叙旧、记仇、追问，而不是每轮重新认识你。

而且这份记忆是**他自己视角的版本**，不是全知剧本：你在他背后做的事，他不会记得；他没在场的那些轮次，往事里只留一行「第 2 轮 ~ 第 4 轮：你不在这里」，内容一个字都不给。

一轮之内也是按顺序的：排在他**前面**开口的人，他当时就听见了；排在他**后面**的人，等他下次上场时，那也已经是发生过的事了。

角色卡也是跨轮复用的。你不用担心他在第二场戏里突然换了个人——引擎会直接用回第一次建的那张卡。

## 时间跳跃不是一段空白

你写「三天后」，这三天里别人不是冻结的。引擎会把这段时间补上：

- **所有人都看得见的那层**：场景变成了什么样（茶馆照常开着，只是靠里那桌一直空着）
- **每个人各自的那条**：他这三天做了什么、状态变成什么样。各自只看到自己那条

补全会跟着角色一起走进下一轮 —— 你回来时，别人不是三天前的样子，而是各自过了三天日子的样子。不想让它补，设置里可以关掉。

---

## 提到知名角色时，它的性格不会写成套话

你在素材里写「（我遇到了金刚狼）」，引擎会：

1. **判断你写的是演出还是概要**。只有一句概要也没关系，它会自己补出时间、地点、氛围、开场画面，以及场上还有谁（包括顺手加的一两个路人）。
2. **给新出场的角色查资料**（中英文维基百科，免 Key，3 秒超时，网络不通就跳过）。
3. 查到了就按资料写卡；查不到但你认识，就用模型自己的知识写——但提示词里明令禁止写「沉默寡言，性格坚毅」这种放在一百个角色身上都成立的废话：

```
✗「实力强大，深藏不露」
✓「动手前习惯先活动一下脖子」
✓「被问到过去时会直接换话题」
✓「嘴上嫌麻烦，但答应过的事一定做到」
```

这类角色还必须填满四项：标志性特征、示例台词、原作里确定的事实、**绝不会做的事**。最后一项专门用来防出戏。

## 装起来

```bash
git clone <这个仓库>
cd interlude
npm install
npm run dev
```

打开 http://127.0.0.1:5273/ ，右上角「设置」填上模型接口即可。

任何 **OpenAI 兼容**的接口都能用：DeepSeek、OpenAI、Kimi、Ollama、各种中转站。

**用 DeepSeek 的话，思考模式可以分两档关。** DeepSeek 的思考模式默认是开的，设置里有两项（只在模型名是 `deepseek-*` 时才显示——别的服务商字段各家不同，引擎不猜也不碰）：

| 开关 | 默认 | 管哪些步骤 |
|---|---|---|
| **简单步骤不思考** | 开 | 拆解、信息分发——判断"这句是台词还是动作""谁背对着谁"用不上思维链，关掉明显变快 |
| **复杂步骤也不思考** | 关 | 导演、角色、场景构建也一起关。更快更便宜，但那些步骤本来就靠模型"想一想"才好看，写出来可能更平 |

打开时引擎会在对应的请求里带上 `{"thinking": {"type": "disabled"}}`。

顺带一提：DeepSeek 在思考模式下会忽略 `temperature`，这是它的规定，不是引擎的问题。

模型是**选项式**的：你只选服务商、填 Key，端点和模型名由它决定——"端点写错、模型名写错"这类问题就不用你操心了。

| | 目前支持 | 它会用的端点与模型 |
|---|---|---|
| **文字模型** | DeepSeek | `https://api.deepseek.com` · `deepseek-flash` |
| **生图模型** | MiniMax | `https://api.minimax.io/v1` · `image-01` |

**场景卡片可以生图**：点一下「生图」，它会把这一轮的地点、气氛和环境描写拼成提示词交给 MiniMax，画出来的图**在卡片吸顶时铺成整个界面的背景**——滚到那个场景时，整个屏幕的底色就是那个地方，滚过去就淡出。画面以环境为主，不出人物正脸（人脸容易崩，也会和你心里的形象打架）。

三个细节：

- **生图成功后描述会自动收起**——有图就能脑补环境了，那段文字不必再占着屏幕。
- **图会存下来**，刷新不丢（生成一次要花钱和时间）。
- 设置里有个**「自动生图」**（默认关）：打开之后，只要出现了新场景就自动画一张。沿用上一个场景的那种不画——同一个地方画两张是浪费。

两个 Key 都只存在你自己浏览器的 localStorage 里，不会发给任何第三方。

**想先看看长什么样？** 不用配 Key，直接打开：

```
http://127.0.0.1:5273/?demo=1
```

这是内置的演示模式——它会用一份脚本化的模型响应，**在浏览器里真的跑一遍完整流水线**，所以看到的内容都是真实产物，不是假数据。（刷新即可回到你自己的数据。）

## 用起来

1. **先写「我自己的人设」**（输入框上方，默认折叠）。你是谁、什么性格、此刻什么状态。它会注入拆解、场景构建和每个角色的判断。
2. **在底部输入框写这一轮。** 具体演出或者一句概要都行：
   - `我说：「你来得比我预想的早。」`
   - `（我遇到了金刚狼）`
3. **点「发送」。** 新的一轮接在下面，视图自动滑过去。

   如果这一轮你什么都不想做，点旁边的 **「什么都不做」** —— 它同样会生成一轮，但走的是另一条路：原文记为「（这一轮我什么都没做。）」，同时给导演一个**强刺激**：世界必须往前走一大步，而且至少要点名一个角色做出实质性的动作。你自己的人设是"不会主动的人"时，这就是你的常规操作。
4. **想改？** 两种：
   - 点「你的输入」块右上角的 **「编辑原文」**，整段重写后重新生成
   - 鼠标移到那一轮的分隔线上，点 **「从这一轮重演」**（原文不变，只是重来一次）

   两种都会丢弃后面的轮次——时间线是线性的。不过没有确认弹窗，顶栏给了 **「↶ 撤销」** 兜底。
5. **想开一条完全无关的新故事线**，用左栏的「＋ 新的对话」。它是真的全新：角色库、记忆、上一幕的场景全部按对话隔离，在新故事里提到「林砚」，引擎不会认出上一场的那个林砚。

## 成人向模式

**先开总闸**：设置 → 项目 → 「允许使用成人向模式」。**默认是关的**，勾上之后输入区才会出现「R18 模式」那个勾选框。不勾这一项，界面上不会出现任何成人向相关的东西。

R18 不是"加个开关让模型说几句露骨的话"。引擎里**每一个环节**都有对应的处理：

| 环节 | 成人向时它做什么 |
|---|---|
| **场景构建** | 氛围可以更私密、更暧昧（光线、距离、体温、沉默的质感），但不改变人物的处境和关系 |
| **你的外化** | 你内心留下的痕迹可以更直白——呼吸、体温、视线停留的位置。但**泄漏多少仍然由人设决定** |
| **信息分发** | 在场的人更容易注意到你身上的细节。空间关系不变——背对着、在另一个房间，该没看见还是没看见 |
| **导演** | 可以指派带有身体距离、试探、挑逗意味的动作，也可以把环境弄得私密、把节奏放慢 |
| **角色** | 可以写性相关的身体反应，台词可以带上明确的欲望 |

**它是「允许」，不是「要求」。** 剧情走到那儿了，就让它发生——不回避、不拉远景、不用"第二天早上"糊过去。你不引导，导演就不主动推进；但你一旦把剧情带到那儿，它必须接住。这种场面里，**文字要直白、直接、粗俗**——含蓄就是扫兴。

**分级记在轮次上。** 勾选框勾上会一直保留（刷新也记得），但每一轮的分级是独立的，你可以这一轮开、下一轮关。回看时，开了的那几轮在分隔线上有红色标记。

**导演也可以要求打开它。** 它判断该到了，就发个请求，客户端替你**把勾打开**。你可以随时取消——取消就说明你暂时不想往那边走，导演那一轮照纯情写，下一轮它觉得该到了还能再提。**两边都不记账，决定权就是"那个勾此刻有没有勾上"**；勾没勾上，导演再想也没用。

### 三条底线

不管哪一轮，提示词里都写死了三条：

1. **性格不能变。** 一个克制的人在这种场景里依然是克制的，只是克制的内容变了。
2. **推进必须是「你会做的事」。** 关系没到那一步就不会跳过去。
3. **不要一步到位。** 节奏由此刻的关系与情境决定，不由分级决定。

还有一条不属于"底线"、而是**红线**，任何分级下都不动：**你扮演的那个人的边界不归任何人决定。**

### 快速入戏：导演有了主动引导的**义务**

勾了 R18 之后，旁边会多出一个「快速入戏」。区别就一句：

> **普通是"他要就给他"，快速是"你负责把他带到那儿"。**

不用等你开口动手，导演会主动把剧情往那边推；你不写的，它来安排。它还有一条硬指标：**这一轮的性评分必须比上一轮高，否则算不合格。**

| 分数 | 意思 |
|---|---|
| **0** | 一点影子都没有 |
| **20** | 有倾向（眼神、话里带钩、距离不对），身体还没碰上 |
| **40** | 身体碰上了——亲、抱、隔着衣服的触碰 |
| **60** | 衣服脱了、身体露出来了 |
| **80** | 已经不是前戏了 |
| **100** | 已经开始了 |
| **100 以上是进度** | 从那之后每多一轮 +10 |

引擎会把**最近四轮它自己打的分**回放给它看（`10 → 10 → 15`）并直接点破："连着几轮几乎没动——那不是在慢热，那是在磨。" **命令它可以抗，自己写下的账没法赖。** 填 0 却写了脱衣服那一套，会跟剧情对不上。

它还会**随时给你几条路选**，摆在每一轮最后：

> ▸ **借着上药靠近** — 我侧身让开门口：「进来吧，先坐下。」然后转身去翻药箱。
> ▸ **让他把湿衣服脱了** — 「你这身得换。」我从柜子里抽了件旧衬衫递过去，然后就站在那儿没走开。

点一下就填进输入框。每条都是**"你"视角的下一步**（不是剧情走向），而且**几条都通向那一步，只是走法不同**——照顾、试探、挑明，挑哪条都不会挑到"没戏"。

它还会替你写掉**这一轮之前的空白**（上一轮到现在之间发生了什么），因为那段铺垫你不想自己一步步写——但**不是这个人的来历**，那是人物小传。

## 三个关键机制

**① 你的台词被锁定。** 你写出口的话原样出现在舞台上，AI 只能补动作和微表情。

**② 信息隔离是硬约束。** 每个角色的上下文里有一份「你确定不知道的事」，别人的内心永远不会进去。所以角色只能靠表情、语气、动作去猜——而且**允许猜错**。

　**每个角色都会经过同一层「信息分发」。** 这一轮实际发生的事——台词、动作、环境、你的细微表现——会被逐条编号，然后由**一次模型调用**转化成每个角色各自接收到的版本：谁背对着所以没看见、谁在走神所以只听见半句、谁把玩笑听成了挑衅。

　默认所有人都收到全部信息，分发层**只报偏差**（漏了什么、听岔成什么、额外察觉到什么）。这样输出短，而且台词原文由编号取回，**不会被模型转述走样**。

　为什么合成一次调用而不是每个角色各判一次：判断「谁背对着谁」这类空间关系**需要全局视角**，单个角色的调用看不见别人在哪；顺带也省掉了 N−1 次调用。

**③ 人设不只是性格。** 每个角色还带着三样东西，它们会实打实地改变引擎的行为：

| | 影响什么 |
|---|---|
| **能力** | 他能做什么。超出范围的事，他做不到——角色不会突然会开锁 |
| **感知** | 他能察觉到什么。读心、超常嗅觉这类会改变他能拿到的信息 |
| **会牵引** | 他的存在会带来什么。招祸体质、被追杀、身负诅咒——场景里会自然长出这类东西 |

　最后一项只在**确实写了**的时候才生效，不会给普通故事硬塞麻烦。

**④ 每一步都能回退，而且只重跑受影响的分支。**

```
规范化 → 拆解 → 场景构建 → 阵容解析 → 局面推进 → 信息分发
                                                    ↓
                              A 的上下文 → A 的反应
                                    ↓ （A 说的话并进下一个人的上下文）
                              B 的上下文 → B 的反应
                                    ↓
                              编排 → 记忆回写
```

改「给 B 的上下文」，只有 B 之后的部分重算，A 原样复用。否则既费钱，角色表现还会漂。

## 目前还没有的

- **真正的时钟**：时间靠你写的「三天后」这类文字推进，引擎不自己记日期（也没有为它做一套日历）。这期间发生了什么会被补全，但那是叙事层的补，不是时间系统。
- **打断与抢话**：角色是按导演排的顺序挨个反应的，还没有"正说着被人打断"这类真正同时发生的交错。
- **逐观察者的误读**：线索带了"可读性"，但还没有为每个角色单独算出他具体读成了什么。
- **世界书 / 正则 / 预设**：酒馆的这些幕间都还没有，也不打算原样照搬。
- **真实网络环境下的端到端验证**：开发时用的是一份脚本化的模型响应，各种中转站的兼容性还需要你帮忙试。
