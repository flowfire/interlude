# 幕间 Interlude

**简体中文** | [English](README.en.md)

**你写一句剧情，剩下的交给引擎。**

它会把你写的东西拆开、搭起场面、派发给场上每个角色，让他们**挨个**反应，再按时间顺序把这一幕接进故事线。

![主界面](docs/images/01-board.jpg)

---

## 它和酒馆（SillyTavern）有什么不一样

两者都是自托管的角色扮演前端，都用自己的 API Key，都能导入自己喜欢的模型。区别在于**「谁来决定该发生什么」**。

酒馆把决定权交给你：你写一条消息，AI 回一条，你看着不对就改提示词、调采样参数、上正则。它是一台**非常好用的单角色对话机器**。

幕间想做的事不一样：**你只负责写剧情，引擎负责调度。** 你把一段素材丢进去，它自己判断这段里哪些是台词、哪些是动作、哪些是场景、哪些是没说出口的；判断谁在场；再由一个「局面」决定这一轮谁先动、世界会怎么变；然后让角色**按顺序挨个**反应 —— 后开口的人看得见先开口的人刚说了什么。

| | 酒馆 | 幕间 |
|---|---|---|
| **一次输入** | 一条消息 = 一次生成 | 一段素材 = 一整轮，场上所有角色**按顺序**挨个反应，后来的人听得见前面的人 |
| **你说的话** | 就是消息本身 | 先被拆解成片段，你说出口的话会被**锁定**，AI 一字不能改 |
| **心理描写** | 直接写出来，所有人都看得见 | 不外传。结合你写的人设，只把「看得见的痕迹」给对方 |
| **信息差** | 上下文全员共享 | 每个角色一份**私有上下文**，含一份「你确定不知道的事」 |
| **配角** | 要自己建卡 | 自动生成；再出场时**复用**同一张卡，人设不漂 |
| **看到了什么** | 只能看最终输出 | 点开任意角色，能看到它这一轮**实际拿到了什么** |
| **改坏了怎么办** | 删消息重来 | 任意一步可编辑，**只重跑受影响的那条分支** |
| **剧情推进** | 你不写就停在那里 | 有一个独立的「**局面**」（这一场戏的导演）在推：它决定世界怎么变，也决定谁先动 |
| **角色的动机** | 靠人设描述 | 每个人卡里写死**「他想要什么」**，每轮他自己决定去干什么，不围着你的输入转 |
| **结构** | 一条聊天记录 | 「对话」（可切换的故事线）＋ 线性轮次 |
| **设置项** | 一大堆 sampler、预设、正则 | 只有三个开关 |

还有一条最不一样的：**你在幕间里说的话，AI 改不了。** 酒馆里你打的内容通常只是"给 AI 看的输入"，而在幕间里它是一份要照着演的剧本——你说出口的台词会原样出现在舞台上，AI 只能补动作、微表情和它自己的话。

### 角色不会围着你转

这是两者在"手感"上差别最大的地方。

酒馆里，剧情是**你一句、AI 一句**推着走的：你不发消息，故事就停在那儿；你一停下来描述自己的状态，AI 也只能对着你刚才那句话做反应。幕间多了一个**不代表任何角色**的行动者——「局面」。它每轮都会问自己一件事：**如果所有人都不作为，接下来会发生什么？** 然后让世界往前走一步：狼群又收紧半步、火塘塌了一角、对方的耐心少了一分。

同时，每个角色的卡里有一条**「他想要什么」**（不是性格，是目标），每一轮都由他自己结合局势决定去干什么。所以你写一句"我听着他的吩咐不动"，金刚狼可以自己去打狼——因为他的目标不是"跟你说话"，是"把你活着带出去"。

万一还是僵住了（你的人设就是不会主动的人，角色也各有各的理由等着），导演会**点名**：挑一个最该动的人，直接告诉他这一轮做了什么——「狼群已经贴到三步之内，站在你身后那个人会是第一个被扑倒的；他动了，第一头狼刚扑上来就被他按进了泥里」。导演通读台本，和演员有同样的权限，只是**只有僵局时他才说**。指令到剧情为止：怎么说、什么表情、什么节奏，仍然是那个角色自己演。**你扮演的角色永远不在点名范围内**——你写什么就是什么，没人能替你动。

引擎里也没有"每个角色每轮必须开口"这种规则。打起来的时候，他们的主战场是动作，不是台词。

**酒馆更适合**：想精细控制每一次生成、依赖世界书（Lorebook）和正则、习惯自己调教提示词。
**幕间更适合**：不想管这些，只想写剧情，然后看一群人自己动起来。

## 心理描写不会被别人读到，但它会「外化」

这是幕间最核心的一条规则。

你写：

```
我其实。。。。（我有点犹豫）。。。。也没那么想回家。。。。
```

引擎**不会**把「我有点犹豫」发给任何角色。它结合你的人设判断：这种犹豫在你身上会留下什么**看得见的痕迹**——

> 话说了一半停下来，手指在伞柄上蹭了一下

角色拿到的是这句话，而不是你的心里话。而且这行字还带着两个数：

- **可读性 35%** — 对方把这条线索读成「他在犹豫」的概率
- **泄漏 50%** — 你这个人在人设上有多藏不住事

人设里写了"城府很深、习惯控制表情"，泄漏就会压到 10~20%；写了"藏不住事"，就会到 70~80%。如果人设就是能完全压住，它也可以**一点都不露**。

## 点开任意角色，看它到底收到了什么

这是幕间区别于普通角色扮演的地方：**没有黑箱**。

点角色卡上的「它收到了什么」，你会看到它这一轮拿到的全部信息，按时间顺序排列：

```
1. 你说：「我其实。。。。」
2. 你注意到「我」：话说了一半停下来，手指在伞柄上蹭了一下
3. 你说：「。。。。也没那么想回家。。。。」
4. 你看我
5. 你说：「我可以。。。。跟你待一会吗。」
```

**注意这是「依次发生」的，不是「并列发生」的。** 你说一句、停一下、再说一句——角色感知到的就是这个顺序，而不是一张"他说了什么 / 他做了什么"的分类清单。

再往下还有：**他亲身经历的往事**（一轮一段，从第 1 轮一路累加，包含他自己当时说过做过什么、当时在想什么），以及一份写明白的「**他确定不知道的事**」。

往事是**逐轮累加、永不重写**的：第 5 轮发出去的东西，就是第 4 轮发出去的东西再往后接一段。这样同一个角色跨轮次的提示词前缀能命中缓存，而且他不会忘掉三轮前说过的那句话 —— 这也是它和「只带最近几句话」的做法最大的区别。

## 角色会记得上一轮

同一个角色再次出场，他会带着前面几轮的记忆上场——他听到的、他说过的、他当时心里想的。所以他能跟你叙旧、记仇、追问，而不是每轮重新认识你。

而且这份记忆是**他自己视角的版本**，不是全知剧本：你在他背后做的事，他不会记得；他没在场的那些轮次，往事里只留一行「第 2 轮 ~ 第 4 轮：你不在这里」，内容一个字都不给。

一轮之内也是按顺序的：排在他**前面**开口的人，他当时就听见了；排在他**后面**的人，等他下次上场时，那也已经是发生过的事了。

角色卡也是跨轮复用的。你不用担心他在第二场戏里突然换了个人——引擎会直接用回第一次建的那张卡。

## 时间跳跃不是一段空白

你写「三天后」，这三天里别人不是冻结的。引擎会把这段时间补上：

- **所有人都看得见的那层**：场面变成了什么样（茶馆照常开着，只是靠里那桌一直空着）
- **每个人各自的那条**：他这三天做了什么、状态变成什么样。各自只看到自己那条

补全会跟着角色一起走进下一轮 —— 你回来时，别人不是三天前的样子，而是各自过了三天日子的样子。不想让它补，设置里可以关掉。

---

## 提到知名角色时，它的性格不会写成套话

你在素材里写「（我遇到了金刚狼）」，引擎会：

1. **判断你写的是演出还是概要**。只有一句概要也没关系，它会自己补出时间、地点、氛围、开场画面，以及场上还有谁（包括顺手加的一两个路人）。
2. **给新出场的角色查资料**（中英文维基百科，免 Key，3 秒超时，网络不通就跳过）。
3. 查到了就按资料写卡；查不到但你认识，就用模型自己的知识写——但提示词里明令禁止写「沉默寡言，性格坚毅」这种放在一百个角色身上都成立的废话：

```
✗「实力强大，深藏不露」
✓「动手前习惯先活动一下脖子」
✓「被问到过去时会直接换话题」
✓「嘴上嫌麻烦，但答应过的事一定做到」
```

这类角色还必须填满四项：标志性特征、示例台词、原作里确定的事实、**绝不会做的事**。最后一项专门用来防出戏。

## 装起来

```bash
git clone <这个仓库>
cd interlude
npm install
npm run dev
```

打开 http://127.0.0.1:5273/ ，右上角「设置」填上模型接口即可。

任何 **OpenAI 兼容**的接口都能用：DeepSeek、OpenAI、Kimi、Ollama、各种中转站。

| 字段 | 例子 |
|---|---|
| baseUrl | `https://api.deepseek.com/v1` |
| model | `deepseek-chat` |
| apiKey | `sk-...` |

Key 只存在你自己浏览器的 localStorage 里，不会发给任何第三方。

**想先看看长什么样？** 不用配 Key，直接打开：

```
http://127.0.0.1:5273/?demo=1
```

这是内置的演示模式——它会用一份脚本化的模型响应，**在浏览器里真的跑一遍完整流水线**，所以看到的内容都是真实产物，不是假数据。（刷新即可回到你自己的数据。）

## 用起来

1. **先写「我自己的人设」**（输入框上方，默认折叠）。你是谁、什么性格、此刻什么状态。它会注入拆解、场景构建和每个角色的判断。
2. **在底部输入框写这一轮。** 具体演出或者一句概要都行：
   - `我说：「你来得比我预想的早。」`
   - `（我遇到了金刚狼）`
3. **点「发送」。** 新的一轮接在下面，视图自动滑过去。

   如果这一轮你什么都不想做，点旁边的 **「什么都不做」** —— 它同样会生成一轮，但走的是另一条路：原文记为「（这一轮我什么都没做。）」，同时给导演一个**强刺激**：世界必须往前走一大步，而且至少要点名一个角色做出实质性的动作。你自己的人设是"不会主动的人"时，这就是你的常规操作。
4. **想改？** 两种：
   - 点「你的输入」块右上角的 **「编辑原文」**，整段重写后重新生成
   - 鼠标移到那一轮的分隔线上，点 **「从这一轮重演」**（原文不变，只是重来一次）

   两种都会丢弃后面的轮次——时间线是线性的。不过没有确认弹窗，顶栏给了 **「↶ 撤销」** 兜底。
5. **想开一条完全无关的新故事线**，用左栏的「＋ 新的对话」。它是真的全新：角色库、记忆、上一幕的场景全部按对话隔离，在新故事里提到「林砚」，引擎不会认出上一场的那个林砚。

## 想往成人向走？每轮单独勾

输入框旁边有个 **「R18 倾向」** 勾选框。**勾选会一直保留**（刷新也记得）——它够显眼，不容易忽略；而每轮的分级是独立存在轮次上的，所以随时可以只给某一轮开或关。

勾上之后，引擎会告诉角色 AI：这一轮可以往那个方向走。但提示词里同时写死了三条底线：

1. **性格不能变。** 一个克制的人在这种场景里依然是克制的，只是克制的内容变了；爱开玩笑的人依然会开玩笑。角色不会因为场景允许就变成另一个人。
2. **推进必须是「你会做的事」。** 关系没到那一步就不会跳过去——该犹豫的还是犹豫，该试探的还是试探。
3. **不要一步到位。** 节奏由此刻的关系与情境决定，不由分级决定。

场景构建和「你的外化」也会收到这个信号：氛围可以更私密、更暧昧，外化线索可以更直白（呼吸、体温、视线停留的位置）。但**泄漏程度仍然由人设决定**——藏得住事的人依然是藏得住的，不会因为勾了 R18 就写在脸上。

开了 R18 的那一轮，在主看板的分隔线上会有一个红色标记，回看时一眼就知道哪几轮是。

想改某一轮的分级：点「编辑原文」，那里有同一个勾选框。**就算原文一个字没动、只切换这个勾选，也算一次改动**，点「保存并重新生成」就会按新分级重演这一轮（后面的轮次会照旧丢弃，顶栏可撤销）。

## 三个关键机制

**① 你的台词被锁定。** 你写出口的话原样出现在舞台上，AI 只能补动作和微表情。

**② 信息隔离是硬约束。** 每个角色的上下文里有一份「你确定不知道的事」，别人的内心永远不会进去。所以角色只能靠表情、语气、动作去猜——而且**允许猜错**。

　**每个角色都会经过同一层「信息分发」。** 这一轮实际发生的事——台词、动作、环境、你的细微表现——会被逐条编号，然后由**一次模型调用**转化成每个角色各自接收到的版本：谁背对着所以没看见、谁在走神所以只听见半句、谁把玩笑听成了挑衅。

　默认所有人都收到全部信息，分发层**只报偏差**（漏了什么、听岔成什么、额外察觉到什么）。这样输出短，而且台词原文由编号取回，**不会被模型转述走样**。

　为什么合成一次调用而不是每个角色各判一次：判断「谁背对着谁」这类空间关系**需要全局视角**，单个角色的调用看不见别人在哪；顺带也省掉了 N−1 次调用。

**③ 人设不只是性格。** 每个角色还带着三样东西，它们会实打实地改变引擎的行为：

| | 影响什么 |
|---|---|
| **能力** | 他能做什么。超出范围的事，他做不到——角色不会突然会开锁 |
| **感知** | 他能察觉到什么。读心、超常嗅觉这类会改变他能拿到的信息 |
| **会牵引** | 他的存在会带来什么。招祸体质、被追杀、身负诅咒——场景里会自然长出这类东西 |

　最后一项只在**确实写了**的时候才生效，不会给普通故事硬塞麻烦。

**④ 每一步都能回退，而且只重跑受影响的分支。**

```
规范化 → 拆解 → 场景构建 → 阵容解析 → 局面推进 → 信息分发
                                                    ↓
                              A 的上下文 → A 的反应
                                    ↓ （A 说的话并进下一个人的上下文）
                              B 的上下文 → B 的反应
                                    ↓
                              编排 → 记忆回写
```

改「给 B 的上下文」，只有 B 之后的部分重算，A 原样复用。否则既费钱，角色表现还会漂。

## 目前还没有的

- **真正的时钟**：时间靠你写的「三天后」这类文字推进，引擎不自己记日期（也没有为它做一套日历）。这期间发生了什么会被补全，但那是叙事层的补，不是时间系统。
- **打断与抢话**：角色是按导演排的顺序挨个反应的，还没有"正说着被人打断"这类真正同时发生的交错。
- **逐观察者的误读**：线索带了"可读性"，但还没有为每个角色单独算出他具体读成了什么。
- **世界书 / 正则 / 预设**：酒馆的这些幕间都还没有，也不打算原样照搬。
- **真实网络环境下的端到端验证**：开发时用的是一份脚本化的模型响应，各种中转站的兼容性还需要你帮忙试。
