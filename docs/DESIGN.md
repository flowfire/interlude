# 幕间 Interlude · 设计方案与项目结构（v2）

> 一句话定位：**你扮演一个角色说话，引擎把你输入的东西自动拆开、分发给场上每个角色 AI，让他们各自（且互不知情地）产生反应；你还能点开任意一个角色，看"它到底收到了什么、于是它才这么反应"。**

参考酒馆（SillyTavern）的角色扮演内核，砍掉全部复杂设置，把"该谁说话、该让谁知道什么、什么时候发生"交给引擎自动判断。

---

## 0. 已确认决策

| 项 | 决定 |
|---|---|
| 架构 | 纯前端 SPA（Vite + React + TS），API Key 存浏览器本地 |
| 接口 | OpenAI 兼容（自填 baseURL / apiKey / model） |
| 角色资料 | 内置卡优先 → 维基补充 → LLM 生成兜底 |
| **用户位置** | **你扮演其中一个角色（`pc`）**，其余角色由 AI 扮演 |
| **台词忠实度** | **你说的话 AI 不能改**；你携带的设定/剧情描述/世界观 → AI 可以改写以贴合人设 |
| **输出形态** | **一个主看板**：显示你的输入 + 各角色对它的反应（按时间顺序）；**点击某个角色的反应，可临时查看**：你的原文被拆成了什么、给了这个角色哪些上下文、它私下的心理是什么 |
| **回退能力** | **每一步都可编辑，编辑后该步之后的所有内容作废并重新生成** |
| 不做 | 不导入酒馆角色卡、不做中途干预、不做图片生成 |
| 界面语言 | 中文 UI + 中文提示词 |
| 心理描写 | 默认不外传，只转成「可见线索」给别人（可能被误读） |
| 时间线 | 自动推算 + 手动校正；幕间空白默认自动补全 |
| 单场并发上限 | 6 个 AI 角色（超出者只做背景交代） |
| 「一轮」定义 | 你发言一次后，**所有在场且该说话的角色都至少说了一句**（或给出明确的沉默判定） |

## 1. 与酒馆的核心差异

| | 酒馆 SillyTavern | 幕间 Interlude |
|---|---|---|
| 交互单元 | 一条消息 = 一次生成 | 你的一句话 = 一整轮（全场上限 6 个角色并发生成） |
| 谁在说话 | 你和单个 AI 角色轮替 | 引擎判定在场者，**每个角色各自**生成反应 |
| 场景描写 | 混在角色输出里 | 独立「环境 Agent」负责 |
| 心理活动 | 直接写出来，人人可见 | 先**外化**成微表情/微动作/语气线索，再被别人（可能错误地）理解 |
| 信息可见性 | 全局共享上下文 | 每个角色一份**私有知识状态**，含"他确定不知道的事" |
| 透明度 | 只能看最终输出 | **点开任意角色，能看到它收到的完整上下文**（这是本项目最独特的地方） |
| 时间 | 只看聊天顺序 | 显式时间轴，支持"三天后"、倒叙、幕间空白补全 |
| 配角 | 用户手动建卡 | 路人自动生成薄卡，反复出现则**自动提升**为常驻角色 |
| 可回退性 | 只能删消息重来 | **任意一步可编辑，只重跑受影响的下游**（DAG） |
| 设置 | 一大堆 sampler/预设/正则 | 只有三个开关（§13） |

## 2. 关键概念

- **素材（Material）**：你这一轮输入的文字。
- **片段（Segment）**：拆解后的最小单元，带类型标签（场景/动作/台词/心理/旁白/世界事实/场外事件/群像）。
- **pc 台词 vs 可演绎内容**（这是本项目最重要的规则）：
  - `speaker === pc` 的台词 → **锁定**，AI 一字不能改，必须原样出现在舞台上；
  - 其余一切（你的场景描写、旁白、设定、世界观、剧情描述，甚至你代笔写的别人的台词）→ `isFact: false`，AI **可以改写**成更贴合各角色人设的版本。
  - 任何片段都可以手动点"锁定"，覆盖上述默认。
- **外化线索（Cue）**：心理活动经"外化器"变成的可见信号，例如"指尖在杯沿上停了半秒"。带两个数值：
  - `leakage` 泄漏度：0 = 完全看不出，1 = 几乎写在脸上；
  - `readability` 可读性：旁观者能读出真实含义的概率。
- **感知（Perception）**：某角色对某条信息的接收记录，分**客观层**（他确实看到/听到了什么）与**主观层**（他理解成什么，**允许错**）。
- **上下文包（ContextBundle）**：派发给某个角色 AI 的完整输入。**它是可查看的**——点开角色反应就能看到。
- **知识状态（Knowledge）**：每角色维护 `known / believed / suspected / unawareOf` 四张清单，`unawareOf` 作为硬性负面约束注入，防止角色全知。
- **轮（Round）**：你发言一次 → 全场的反应。完成标准是覆盖率——所有在场且"该发言"的角色都至少产出一个台词节拍（或带理由的沉默判定）。
- **幕间空白（Interlude Gap）**：两个场景之间的时间跳跃区间，引擎抽取其中发生的事并判定谁该知情。
- **步骤（Step）**：流水线的一次可编辑、可重跑的中间产物。**一切皆步骤**，这是回退能力的底座。

## 3. 端到端流水线（8 个 Stage，每个 Stage = 若干可编辑 Step）

```
你的输入
  │
  ├─ S0 规范化 ─────────── 纯代码：分段、标号、引号结构识别
  ├─ S1 拆解 ───────────── LLM#1：→ Segment[]（类型、说话人、接收人、能否改写）
  ├─ S2 场景构建 ───────── LLM#2：判断「具体演出」还是「概要」；把概要展开成可开演的场面；确定在场者（含路人）
  ├─ S3 阵容解析 ───────── 代码 + LLM#3：实体 → 角色卡（匹配/新建/路人薄卡）
  ├─ S4 上下文分配 ─────── 代码（可选 LLM）：为每个角色组装私有上下文包  ★可查看
  ├─ S5 分角色反应 ─────── LLM×N 并发：每个角色独立生成节拍 + 感知
  ├─ S6 外化与失真 ─────── LLM×少量：心理→线索；线索→（可能错的）理解
  ├─ S7 编排 ───────────── LLM#1：按时间顺序排列反应 + 覆盖率检查/补白
  └─ S8 状态回写 ───────── 纯代码：时间线、记忆、关系、路人提升
```

### S0 规范化（无 LLM）
- 按空行/换行切块，保留原文偏移 `sourceRange`（用于在"点开角色"时高亮你原文的哪一段）。
- 规则预标注（省 LLM 成本）：引号内 → 候选 `speech`；`XX 说/道/问` → speaker；`心想|暗想|心道` → 候选 `inner`；`三天后|翌日|当晚` → 时间标记。
- 预标注只是提示，S1 可覆盖。

### S1 拆解（LLM #1）
输出严格 JSON（zod 校验）：

```jsonc
{
  "segments": [
    { "id": "s1", "kind": "scene",  "text": "雨停了，青石板上还积着水洼。", "location": "茶馆门口",
      "speaker": null, "isFact": false, "visibility": "public", "confidence": 0.95 },
    { "id": "s2", "kind": "speech", "text": "你来得比我预想的早。", "speaker": "沈栖", "addressee": ["林砚"],
      "isFact": true, "visibility": "public", "confidence": 0.97,
      "lockReason": "pc 台词，锁定" },
    { "id": "s3", "kind": "inner",  "text": "她果然还是来了。", "subject": ["林砚"],
      "isFact": false, "visibility": "private", "confidence": 0.8 }
  ],
  "entities": [
    { "mention": "沈栖", "kind": "person", "role": "pc" },
    { "mention": "林砚", "kind": "person", "role": "present" }
  ],
  "timeMarkers": [{ "text": "三天后", "kind": "elapsed", "value": "P3D" }]
}
```

- `isFact` 的**自动判定规则**：`speaker === pc` → `true`；其余 → `false`（可演绎）。UI 上每段有个锁图标可手动翻转。
- `visibility: private` 的片段（心理）不进公共舞台，只进拥有者与"你能看的私密层"。
- 低置信片段在拆解预览里高亮，等你一键改标签，改动会回存为你的**个人标注偏好**。

### S2 场景构建（LLM #2）
职责：把你写的东西变成**一个可以立刻开演的场面**。

先判断你写的是哪一种：
- `dialogue`：已经有实际演出（有人说话、有具体动作）→ 只补舞台，不改内容
- `outline`：只是一句概括（「我遇到了金刚狼」「三天后我们打了一架」）→ 展开成场面
- `mixed`：两者都有

```jsonc
{
  "inputMode": "outline",
  "time": "三天后的傍晚",
  "place": "城郊废弃的汽车旅馆门口",
  "atmosphere": "雨刚停，路灯坏了一半",
  "situation": "你推门出来，正好和蹲在台阶上擦爪子的人打了个照面。",
  "opening": [
    "雨刚停，柏油路面上积着一层薄水，把歪掉的霓虹招牌映成模糊的一片红。",
    "旅馆门口只有一盏灯还亮着，灯下的台阶上坐着一个人，正低着头擦什么东西。"
  ],
  "pcProfile": "二十出头，外套肩膀湿了一片，站在门口没动——看起来不像常来这种地方的人。",
  "present": [
    { "name": "金刚狼", "role": "坐在台阶上的人", "brief": "正低头擦爪子", "kind": "character", "active": true },
    { "name": "前台老头", "role": "旅馆前台", "brief": "隔着玻璃打瞌睡", "kind": "extra", "active": false }
  ],
  "establishedBeats": [
    { "kind": "action", "character": "我", "text": "推门出来，站在台阶上" }
  ]
}
```

两条关键规则：

1. **被提到的人一律算在场。**「我遇到了金刚狼」意味着金刚狼就在场，哪怕素材里他一句话都没说。绝不因为"没有台词"就判定他不出场。
2. **`pcProfile` 只写看得见的。** 它是派发给其他角色的「对面站着的这个人」——性别年龄感、穿着、状态、姿态、别人第一眼会注意到什么。用户填写的自我人设属于内心层面，不会被派发。

还有一条**保险丝**（`ensurePresentHasActors`）：如果模型判定「没有需要反应的角色」，但素材里明明有人名，引擎会强制把他们拉回在场名单并标记为需要反应。这是为了兜住概要式输入最容易踩的坑。

### S3 阵容解析（代码 + LLM #3）
每个实体走资料阶梯：

```
① 已有角色卡（名字/别名精确匹配）       → 命中
② 内置资料库 src/data/cards/*.json    → 命中，实例化
③ 维基摘要（REST API，免 key，CORS 可用）→ 生成卡，source=wiki
④ LLM 凭空生成                        → source=generated，UI 标「推测」
```

| tier | 含义 | 处理 |
|---|---|---|
| `pc` | 你（唯一） | 台词锁定，引擎不替你决定关键选择 |
| `major` | 主要角色 | 完整卡 + 长期记忆 + 每轮参与生成 |
| `minor` | 次要角色 | 精简卡 + 场景级记忆 |
| `extra` | 次抛路人 | **薄卡**（名字/身份/一个特征/说话风格），只在需要的场景出现 |

**路人提升**：出现或提及累计 ≥3 次、或与主要角色建立关系边、或你手动点"提升" → 升为 `minor`，用 LLM 基于他**已有表现**补全完整卡（一致性约束："他此前表现为……请保持一致"）。

### S4 上下文分配（代码为主）★ 这是"点开能看"的核心内容
为每个角色组装一份**私有上下文包**，并同时存档（供你在 UI 里查看）：

```jsonc
{
  "characterId": "lin-yan",
  "self": { /* 角色卡：人设 / 说话风格 / 习惯小动作 */ },
  "state": { "mood": "戒备", "location": "城南茶馆", "physical": "袖口湿了" },
  "sceneSet": [ /* 只给他看的环境信息 */ ],
  "heard": [ { "kind": "speech", "text": "你来得比我预想的早。", "from": "沈栖", "channel": "亲耳听到" } ],
  "recalled": [ /* 检索回来的历史记忆，带时间与来源 */ ],
  "toldDuringGap": [ /* 幕间空白里他得知的事 + 他是怎么知道的 */ ],
  "youDoNotKnow": [ "沈栖父亲入狱的隐情", "沈栖今天为什么来" ],   // ← 硬约束
  "mustSpeak": true,
  "beatBudget": { "speech": 1, "action": 1, "cue": 2 }
}
```

- `youDoNotKnow` 是硬约束；S7 后还有一次**出戏检测**（角色是否说出了他不可能知道的事）。
- `recalled` 走本地检索（§7），不是把全部历史塞进去。

### S5 分角色反应（LLM × N，并发）
每个角色一次调用，**互不可见对方的即兴发挥**（保证独立性）：

```jsonc
{
  "characterId": "lin-yan",
  "beats": [
    { "kind": "cue",    "text": "右手在门框上顿了一下", "timing": "immediate" },
    { "kind": "speech", "text": "你来得比我预想的早。", "addressee": ["沈栖"], "timing": "after:user" },
    { "kind": "action", "text": "把湿伞靠在门边，坐到靠里的位置", "timing": "immediate" },
    { "kind": "speech", "text": "坐吧，靠窗那桌别坐。", "addressee": ["沈栖"], "timing": "after:other-reacts" },
    { "kind": "inner",  "text": "她手上没有戴那枚戒指。", "timing": "immediate" }
  ],
  "perceptions": [
    { "sourceId": "s2", "observed": "她说这句话时没有看我",
      "interpretation": "她不想让我看出她在意", "accuracy": 0.6,
      "emotionalImpact": "轻微被刺到", "reactionIntent": "用玩笑挡回去" }
  ],
  "newMemory": [ /* kind: witnessed/told/inferred/did/rumor */ ],
  "stateDelta": { "mood": "收起了玩世不恭", "intent": "试探沈栖是否知情" },
  "knowledgeDelta": { "learned": ["沈栖今天没戴订婚戒指"] }
}
```

- **顺序语义**：`timing` 用标签而非序号（`immediate` / `after:user` / `after:other-reacts` / `after:<id>` / `later`），由 S7 翻译成真实顺序，避免并发时的因果冲突。
- 超过 6 个在场角色时，第 7 个起只生成一句话的背景交代，不参与完整往返。
- `minor` / `extra` 用廉价模型 + 更小的 `beatBudget`。

### S6 外化与感知失真
1. **外化**：每个 `inner` 节拍 → 0..n 条 `Cue`：
   ```jsonc
   { "characterId": "lin-yan", "channel": "face", "visible": "嘴角的笑维持了半秒就收住了",
     "leakage": 0.4, "readability": 0.3 }
   ```
   `leakage = f(自制力, 情绪强度, 场合公开度)`；完全藏得住 → `channel: "none"`（什么也没露）。
2. **感知**：旁观者只拿到 `Cue.visible` 这一句客观描述，各自经过"性格 + 关系 + 偏见"过滤，产出**可能不符真实含义**的 `interpretation`：
   ```
   accuracy = clamp(base(关系亲密度) + readability + familiarity(了解程度) − bias(偏见/情绪), 0.05, 0.95)
   ```
3. **禁止越权**：任何角色不得复查他人 `inner`；S7 前有校验器拦截越权输出。

**只有"你"能看全**：舞台上其他人只看到线索，但私密层（点开角色卡的"心理"页签）会告诉你：真实内心是什么、外化成了什么线索、别人读成了什么、读错了多少。这是这套系统最有趣的地方。

### S7 编排（LLM #1）
把全场节拍按时间顺序排好，产出**主看板的展示结构**：

```jsonc
{
  "blocks": [
    { "order": 1, "kind": "scene",  "text": "雨停了，青石板上还积着水洼。" },
    { "order": 2, "kind": "speech", "characterId": "pc",     "text": "你来得比我预想的早。", "locked": true },
    { "order": 3, "kind": "action", "characterId": "lin-yan","text": "推门进来，袖子湿了半截。" },
    { "order": 4, "kind": "cue",    "characterId": "lin-yan","text": "他的笑维持了半秒就收住了。" },
    { "order": 5, "kind": "speech", "characterId": "lin-yan","text": "坐吧，靠窗那桌别坐。" }
  ],
  "remarks": [ { "kind": "simultaneous", "orders": [3, 6], "note": "两人几乎同时开口" } ]
}
```

编排约束（按优先级）：
1. **锁定的 pc 台词一字不改**，必须出现；
2. 因果先后：`after:other-reacts` 必须排在触发它的节拍之后；
3. 同一时刻的动作可并列；
4. 环境节拍穿插在节拍转换处，像舞台指示；
5. **覆盖率保证**：扫描在场角色，缺台词者 → 触发一次"补白"轻量调用（"你必须说一句话，或者给出明确沉默的理由"），最多 2 轮；
6. 无法裁决的冲突 → UI 标黄，交给你决定，不静默编造。

### S8 状态回写（无 LLM）
推进时间轴、写入每角色记忆、更新关系边与心境、判定路人提升、统计 token 与调用次数。
**所有写入都带 `producedByStepId`**，以便回退时精确撤销（§9）。

## 4. 可回退的步骤图（StepGraph）——架构底座

你要的"每一步都能编辑，然后这一步之后的所有内容作废并重新生成"，本质是**一个可编辑、可选择性重跑的 DAG**。

```ts
export type StepStage =
  | 'normalize' | 'segment' | 'scene' | 'cast'
  | 'context' | 'roleplay' | 'exteriorize' | 'compose' | 'commit';

export interface Step<TOut = unknown> {
  id: string;
  roundId: string;
  stage: StepStage;
  label: string;                     // "林砚 的反应" / "拆解" / "给林砚的上下文"
  deps: string[];                    // 直接上游 stepId（DAG 边）
  inputSnapshot: unknown;            // 当时的完整输入（含注入 LLM 的上下文），可回看
  output: TOut;                      // 产物，**可编辑**
  status: 'pending' | 'done' | 'stale' | 'error';
  lockedByUser: boolean;             // 锁定后重跑时跳过
  editedByUser: boolean;             // 是否被人手改过（重跑会覆盖，需提示）
  model?: string;
  cost?: { calls: number; tokensIn: number; tokensOut: number; ms: number };
}

export interface Round {
  id: string;
  userInput: string;
  steps: Record<string, Step>;
  rootStepIds: string[];
  status: 'draft' | 'running' | 'done' | 'error';
  createdAt: string;
}

// 副作用账本：所有写入状态的东西都记录来源步骤，便于撤销
export interface LedgerEntry {
  id: string;
  producedByStepId: string;
  kind: 'memory' | 'relation' | 'timeline' | 'card' | 'state';
  targetId: string;
  payload: unknown;
}
```

行为规则：

| 操作 | 结果 |
|---|---|
| 编辑某个 Step 的 `output` | 该 Step 标 `editedByUser`，**递归把所有下游 Step 标 `stale`** |
| 点「从这一步重跑」 | 只重算 `stale` 的 Step；未 stale 的复用缓存（省钱、省时间） |
| 点某 Step 的「锁定」 | 重跑时跳过它，并用它的产物作为下游输入 |
| 点某 Step 的「查看」 | 显示 `inputSnapshot`（"它当时收到了什么"）与 `output` |
| 重跑前 | 先按 `LedgerEntry.producedByStepId` 撤销该 Step 及其下游产生的记忆/关系/时间线写入 |
| 角色之间无依赖 | 改「林砚的反应」**不会**让「阿七的反应」重跑（DAG 分支隔离） |

**为什么这条设计值钱**：拆解错了某个标签，只需重跑受影响的那条分支；某个角色的反应不满意，其他五个角色的反应可以直接复用，不必重抽（否则每次重来都在烧钱且角色表现会变）。

## 6. 提示词体系

`src/engine/prompts/` 每类 Agent 一个模板，统一由 `buildPrompt(stage, ctx)` 组装：

| 文件 | 职责 | 关键约束 |
|---|---|---|
| `segmenter.ts` | 拆解素材 | 只输出 JSON；台词必须归属到人；**pc 台词标 isFact=true**；不确定标 narration |
| `scene.ts` | 判断演出/概要、展开场面、确定在场者 | 被提到的人一律算在场；pcProfile 只写看得见的 |
| `castResolver.ts` | 从资料生成角色卡 | 有资料**不许编造**；无资料必须标注"虚构" |
| `roleplay.ts` | 单角色反应 | 严格第一人称视角；只用上下文包里的信息；不得复述他人内心 |
| `exteriorizer.ts` | 心理→可见线索 | 只描述"看得见/听得见"的，禁止解释含义 |
| `perceiver.ts` | 线索→理解（允许错） | 必须体现该角色的偏见与关系，并给出理由 |
| `composer.ts` | 时序编排 | pc 台词一字不改；先因果后文采 |
| `coverage.ts` | 补白 | 只允许一句话 + 一个动作，或明确沉默 |

通用约定：
- 强制 JSON：优先 `response_format: { type: 'json_object' }`，不支持则提示词内约定 ```json 块 + 解析兜底。
- 输出一律 zod 校验；失败 → 附带错误重试 1 次 → 再失败降级（规则结果或跳过并标记）。
- `temperature`：拆解/编排 0.2；角色反应 0.85；外化 0.6。

## 7. 信息传递模型（"真实世界不会百分百传递信息"）

```
真实意图 (inner)
   │ 外化：leakage = f(自制力, 情绪强度, 场合公开度)
   ▼
可见线索 (cue.visible)      ← 客观、不含解释
   │ 传输：只有在场者、注意力在对方身上的人能收到
   ▼
观察者接收 (observed)
   │ 解码：accuracy = f(关系亲密度, readability, 熟悉度, −偏见)
   ▼
观察者理解 (interpretation) ← 允许错，且错得符合人设
   │
   ▼
观察者的反应 (beat) ──→ 又成为别人眼中的新线索 → 循环
```

三条硬规则：
1. **不越权**：任何人不得读取他人 `inner`；出戏检测器拦截。
2. **可错但不可乱**：误读必须由该角色的 `bias / 关系 / 当下情绪` 解释得通，不能随机错。
3. **传播衰减**：信息每转述一次，准确性打折并可能变形，记为 `kind: 'rumor'` 并带上来源。

## 8. 时间线与"向前追溯"

### 时间推算
- 素材含相对时间词 → 相对上一轮锚点推算（`P3D`、`PT30M`）。
- 无时间词 → 默认承接上一轮（+5 分钟），标 `assumed: true`，UI 顶部提示"时间：假定为 5 分钟后，可改"。
- 倒叙/回忆 → `flashback: true`，写入时间轴但**不推进主线时钟**。

### 幕间空白补全（对应"三天后提到这三天发生的事"）
1. 计算锚点到当前之间的 gap；
2. 从你的素材抽取落在 gap 内的 `offscreenEvents`；
3. 对每个角色判定知情与渠道：亲历 → `witnessed`；被明确告知 → `told`（记录告知者）；只闻风声 → `rumor`（打折）；**不在场也没人告诉他 → 进 `unawareOf`**；
4. **幕间补全**（默认开）：每个角色各生成 1–3 条"这段时间我在做什么 / 我是怎么知道的"，写入记忆，供本轮动机使用；
5. UI 上时间轴用一个可展开的"空白区段"展示：点开能看到"这三天每个人各自经历了什么"。

### 向前追溯（检索）
本地检索，不依赖向量库（可选 embedding 增强）：

```
score = 0.35·实体重叠 + 0.2·关键词重叠 + 0.25·近因(时间衰减) + 0.2·显著性(salience)
        + 加成：同场景 / 同一关系边 / 你标为"伏笔"
```

- 每角色取 Top-K（默认 K=8）注入 `recalled`；
- S2 的 `retrievalQueries` 发起检索；
- 长剧情下每 20 轮做一次**分层摘要**（轮摘要 → 篇章摘要），检索优先命中摘要再展开原文。

## 10. 记忆系统

- 每角色一条**记忆流**（append-only），含绝对时间、渠道、情绪、显著性、`producedByStepId`。
- 三层：`原始记忆条` → `轮摘要` → `篇章摘要`。
- 写入时机：S5 角色自报 `newMemory` + S8 引擎补写"他旁观到的事"。
- 检索：§8 的加权打分；注入时按预算裁剪（默认 ≤1200 tokens/角色）。
- **印象漂移**：关系边上的 `attitude / trust / bias` 由每次互动小幅更新（规则驱动，避免 LLM 乱改数字）。

### 点开一个角色反应 → 「它到底收到了什么」浮层

主看板只呈现「你的输入 + 每个 AI 的输出」，不把 AI 的内心摊在台面上。
但点开任意一张反应卡，就能看到这个 AI 究竟收到了什么——这是本项目最有辨识度的交互，含三个页签：

| 页签 | 内容 |
|---|---|
| **上下文包** | S4 给他的完整 `ContextBundle`：人设、心境、他听到的、他回忆起的、幕间得知的、**他确定不知道的** |
| **拆解对照** | 你的原文被拆成了哪些片段，用两种颜色高亮：**给了他** / **没给他**（以及为什么没给） |
| **原始输出** | 该角色 LLM 返回的原始 JSON（含它自己产出的内心活动），**可直接编辑**（编辑后该步之后全部作废） |

你自己扮演角色的内心只存在于你的输入里，**不会被派发给任何其他角色 AI**。

### 历史 / 回退面板

- 以树形展示本轮所有 Step（拆解 → 上下文 → 各角色反应 → 外化 → 编排）。
- 每个 Step：`查看` / `编辑` / `锁定` / `从这一步重跑`。
- 编辑后下游渐变灰（stale），顶部提示"将从这一步重跑 N 个下游步骤"。
- 跨轮的历史同样可回退。

### 交互原则
- 默认零设置，只有三个开关（§13）。
- 所有 AI 的判断都可见、可改：改标签、改时间、改 tier、删角色、改台词归属，改动沉淀为偏好。
- 「拆解预览」先只跑 S0–S3（便宜），把拆解结果和阵容摊开让你确认，再点「开演一轮」跑 S4–S8。**这是主要的成本闸门。**

## 13. 只需要三个开关

1. **演绎自由度**（默认：中 —— 角色可以加新台词和动作，但不得改变你设定的剧情走向）
2. **幕间补全**（默认：开 —— 时间跳跃时自动补全各角色在空白期做了什么）
3. **误读强度**（默认：中 —— 角色之间的理解会有偏差但大体靠谱；调高则更"鸡同鸭讲"）

其余全部自动。设置面板只有这三个 + API 配置。

> 注：原先的"台词是否可改写"不再是开关，而是**规则**——你的台词锁定，其余可演绎，任何片段都能单独上锁。

## 15. 风险与对策

| 风险 | 对策 |
|---|---|
| 厂商 CORS / 接口差异 | 设置里给"直连 / 代理"开关（代理地址用户自填）；M0 先实测 |

## 16. 已确认（第二轮）

1. **主看板形态**：只要按时间顺序排列的「你的输入 + 各角色反应卡」，不做交织成整幕剧本的视图。
2. **AI 的内心**：主看板不展示。真正的内心只有你自己角色的（来自你的输入），且**不会派发给任何其他角色 AI**。点开一个角色反应，要看的是「它收到了什么」（上下文包 / 拆解对照 / 原始输出）。
3. **场上角色判定**：引擎从你的素材里自动推断（你提到了谁、谁在那个地点），零操作。
4. **不做**：酒馆角色卡导入、中途干预、图片生成。

### 交互变更（按第三轮反馈）

原来是「拆解预览 → 确认 → 再开演」两步。你要求一步到位，于是改成：

- 按钮叫 **「发送」**，点下去后台一次跑完：规范化 → 拆解 → 阵容解析 → 每角色上下文 → 每角色反应 → 编排。
- 拆解不再是一个前置步骤，而是**事后可查可改的详情**：点主看板里「你的输入」那一块即可展开/收起。
- 每张角色反应卡上有 **「它收到了什么」**，点开就是那个角色这一轮实际拿到的完整上下文，外加「拆解对照」：你的原文哪些片段给了他、哪些没给。
- 生成过程中顶部实时显示哪个步骤在跑。

步骤图从线性变成按角色分叉：

```
规范化 → 拆解 → 阵容解析 ─┬─ 给A的上下文 → A的反应 ─┐
                          ├─ 给B的上下文 → B的反应 ─┼→ 编排
                          └─ 给C的上下文 → C的反应 ─┘
```

改「给B的上下文」，只有 B 的反应和编排重跑，A 和 C 原样复用。`runSteps` 按依赖分层并发执行，互不依赖的角色反应会真并发。

### 第四轮变更：场面展开与「我自己的人设」

三个问题：

1. **布局反了**：输入框应该在底下，主看板在上面展示整轮交互流程。已改。
2. **缺「我自己的人设」**：新增可实时编辑的输入（默认折叠在输入框上方）。它注入 S1 拆解、S2 场景构建、S3 阵容、S5 反应的提示词；但派发给角色 AI 的只有 S2 归纳出的 `pcProfile`（看得见的样子），人设本身不派发。
3. **概要输入被判成「无需交互」**：`（我遇到了金刚狼）` 之前会走进"素材里没有其他出场人物"的死路。根因是阵容解析把"没说话"当成了"不在场"。修法是插入 S2 场景构建并加保险丝：
   - S2 判断 `inputMode`，概要就走"展开成场面"的分支：补时间、地点、氛围、开场画面、在场者、开场已发生的节拍；
   - 阵容解析不再自己判断谁在场，改为**以 S2 的在场名单为准**（名单里的人必有卡，名单外的人丢掉）；
   - `ensurePresentHasActors()` 作为保险丝：模型说没人需要反应、但素材里有人名时，强制拉回在场名单。

流水线因此变成：

```
规范化 → 拆解 → 场景构建 → 阵容解析 ─┬─ 给A的上下文 → A的反应 ─┐
                                     ├─ 给B的上下文 → B的反应 ─┼→ 编排
                                     └─ 给C的上下文 → C的反应 ─┘
```

`composeScene` 也改为以 S2 的 `opening` 和 `establishedBeats` 为骨架，并保留一条保险丝：如果 S2 漏抄了你写的台词，编排会把素材里属于你的台词动作补回来并锁定。

### 第五轮变更：连续剧情流与跨轮记忆

两个根子上的问题：

**1. 轮次被切开了。** 原来点某一轮就只显示那一轮，看不到剧情全貌。现在主看板是**一条连续的剧情流**：所有轮次从上到下排下来，新的一轮追加在末尾并自动滑过去；左栏的轮次列表退化为**目录锚点**（点击 `scrollIntoView`），不再切换视图。长剧情用 `content-visibility: auto` 让浏览器跳过屏幕外轮次的渲染。

**2. 角色没有跨轮记忆。** 现在补上了三层：

- **角色库跨轮复用**：S3 阵容解析先查库，以前出场过的角色直接复用他的卡（`usedModel: false`，零调用），只给新角色调模型。同名同 `stableCharacterId`，所以跨轮身份稳定。
- **S8 记忆回写**：一轮结束多跑一个 `commit` 步骤，为每个参与角色写一条**他自己视角**的记忆 —— 「他听到的 + 他说的 + 他做的 + 他当时想的」，外加场面定位。特别注意：记忆不是全知剧本，他没在场的事不会进他的记忆。
- **注入下一轮**：S4 组装上下文时 `recallFor()` 取该角色最近 N 段记忆放进 `ContextBundle.recalled`。第十二轮起，提示词改为直接给**往事全文**（见下方「第十二轮变更」），摘要不再单独发送 —— 它现在是压缩的原料，不是注入的内容。

**关键设计：角色库和记忆都不单独存储，而是从步骤图派生**（`engine/memory/library.ts`）：

```ts
getCastLibrary(steps)  // 合并所有 cast 步骤的产物，后者覆盖前者
getMemories(steps)     // 汇总所有 commit 步骤的 entries
```

好处是回退零成本：删掉某一轮的「记忆回写」步骤，那一段记忆就随之消失；重跑某条分支，记忆跟着重算。不需要维护任何"撤销记忆"的补偿逻辑，也不会出现"步骤回退了但记忆还留着"的不一致 —— 有测试专门守这条。

流水线因此变成：

```
规范化 → 拆解 → 场景构建 → 阵容解析 ─┬─ 给A的上下文 → A的反应 ─┐
                                     ├─ 给B的上下文 → B的反应 ─┼→ 编排 → 记忆回写
                                     └─ 给C的上下文 → C的反应 ─┘
```

### 第六轮变更：你的外化（S2b）

反馈是：`（我有一点尴尬）` 判成"不该给对面"，原则上对；但**结合人设可以推断出外在表现，那个表现本来就该给对方看**。

在这之前机制只做了一半：心理不外传 ✅，外化 ❌。补上 S2b `exposure`：

- 输入：你写的内心片段 + 你的自我人设 + 场面 + 在场者
- 输出：0~3 条 `PcCue`，每条含 `visible`（别人眼里的现象）、`channel`、`leakage`（你这个人有多藏不住事）、`readability`（别人读出真实心情的概率）
- 提示词写死两条：**只写现象不写解释**；**泄漏程度必须符合人设**（城府深的人 leakage 0.1~0.3，藏不住事的人 0.7~0.9）。并且明确允许「一点都不露」——返回空数组比硬编一个表情好。
- 素材里没有内心活动时直接跳过，不调模型。

**安全边界在类型上就分开**：

```ts
interface PcCue { hidden: string; visible: string; leakage: number; readability: number }  // 引擎侧，给你看
interface ObservedCue { visible: string; readability: number; channel: CueChannel }        // 给角色 AI 的，没有 hidden
```

`ContextBundle.pcCues` 的类型是 `ObservedCue[]`，所以 `hidden` 在类型层面就进不去角色的上下文。有一条测试直接 `JSON.stringify(bundle)` 断言搜不到你的真实内心。

S0 规则层同步补齐：`（…）` 括号里带情绪词的（尴尬 / 紧张 / 心虚 / 后悔…）判为 `inner`；带动作的仍判动作。

舞台（S7）上多一类 `pc-cue` 块，排在「你说了 / 做了什么」之后、角色反应之前；角色提示词里对应出现一节「你注意到的「你」的样子」，并附一句"这些只是现象，你很可能猜错"。

流水线变成：

```
规范化 → 拆解 ─┬→ 场景构建 ─┬→ 你的外化 ─┐
               │            └→ 阵容解析 ─┴┬─ 给A的上下文 → A的反应 ─┐
               │                          ├─ 给B的上下文 → B的反应 ─┼→ 编排 → 记忆回写
               │                          └─ 给C的上下文 → C的反应 ─┘
```

### 第七轮变更：一轮之内的时序

反馈：用户是**按时间顺序**写的，但引擎把同一轮里依次发生的事当成了并列归类。例子：

```
我其实。。。。 （我有点犹豫） 。。。。 也没那么想回家。。。。
（我看着他）我可以。。。。跟你待一会吗。
```

被读成"4 段心理/动作 + 1 段台词"，实际是"说一句 → 犹豫 → 再说一句 → 看他一眼 → 又问一句"。

三处根因，逐条修：

1. **拆解没有保留时序语义。** 提示词新增三条硬规则：输出必须保持原文顺序、不得按类型重排；一段话被括号打断时括号前后是**两次独立发言**；**不得因为没有引号就判成心理或旁白**（带省略号、被停顿切开的明显是台词）。见 `prompts/segmenter.ts` 第 10~12 条。

2. **编排把顺序打乱了。** 原来的 `composeScene` 按类型分组重排（先所有 scene、再所有 pc-action、再所有 pc-speech……），直接抹掉了"句 → 停顿 → 句"的节奏。现在改为**按 `sourceRange` 严格重建时间线**：遍历原文顺序，逐条翻译成舞台块。场景文本用 `seenScene` 去重，但**台词一律不去重**（否则两个人各说一句「嗯。」会丢掉一句）。

3. **角色感知也是分组的。** `ContextBundle` 原来的 `heard / seen / ownPriorLines` 是三个分类数组，角色看到的是"他听到的（若干）+ 他看到的（若干）"，而不是"先发生什么、后发生什么"。现在新增 `perceived: PerceivedEvent[]`（`kind` + `from` + `text` + `self`），**按原文顺序**，角色提示词用它渲染成带编号的事件序列：

```
【刚才按时间顺序发生的事】
1. 你说：「我其实。。。。」
2. 你注意到「我」：指尖在裤缝上蹭了一下
3. 你说：「也没那么想回家。。。。」
（这些是依次发生的，不是同时发生的。标着「你说」的都是你已经说过的，不要重复。）
```

两处配套改动：

- **切块按括号切开。** `splitIntoBlocks` 先把 `A（B）C` 拆成 `A` / `（B）` / `C` 三块，让规则层就能分别标注，也让模型更容易看出"括号把台词切开了"。
- **外化线索带 `fromIndex`。** 外化器输出的每条线索标明来自第几条内心（提示词里给内心编号），编排时据此把线索**插回它原本的时间位置**。概要模式下没有对应内心片段时，线索会在你的内容之后兜底补上，不会丢。

### 第八轮变更：知名角色的资料阶梯

反馈：知名角色（金刚狼）的人设写得太简陋，容易出戏。

根因是 §9 那张资料阶梯表一直只实现了最底下一档（LLM 凭空生成）。现在把上面几档补上：

**① 维基检索（新增）** `engine/research/wiki.ts`

- 对**这一轮新出场**的角色并发查中英文维基摘要，取信息量更大的那份
- `zh.wikipedia.org` / `en.wikipedia.org` 的 REST summary 接口：免 key、允许跨域
- 3 秒超时，网络不通或没有词条一律静默返回 `null`（不报错、不阻塞）
- 消歧义页直接丢弃（信息量还不如模型自己的知识）
- 查到的摘要存档进卡片的 `researchNote`，重跑时不必再查

**② 三档写法写进提示词** `prompts/cast.ts`

| 档位 | 触发条件 | 提示词要求 |
|---|---|---|
| A | 有参考资料 | 资料权威、不得矛盾，把卡写厚 |
| B | 无资料但模型认识 | 用自身知识，**唯一要求是具体**，必须填满 signature / voiceSamples / canonAnchors / boundaries |
| C | 完全不认识 | 只按素材写薄卡，不得编造身世 |

B 档的提示词里直接给了反例清单（「沉默寡言，性格坚毅」「外表冷酷内心温柔」「实力强大深藏不露」）并注明"放在一百个角色身上都成立，等于没写"，要求改写成可辨认的具体行为。

**③ 角色卡加四个字段**

```ts
persona: {
  signature: string[]      // 标志性特征：具体到熟悉原作的人一眼认出
  voiceSamples: string[]   // 符合他说话方式的示例台词 —— 把握语气用，不是必须说的
  canonAnchors: string[]   // 原作确定的事实，包含能力及其限制
  boundaries: string[]     // 绝不会做的事/说的话（防出戏）
}
canonical: boolean         // 是否知名角色
franchise: string          // 出处
source: 'wiki' | 'model' | 'material' | 'manual'   // 资料依据，UI 上标出来
```

角色提示词里把这四项展开成四节，并明确 `voiceSamples` 是"语气示例，不是你必须说的台词"——否则模型会机械照抄。

**④ 一条红线**：不确定的细节宁可不写。写错一个知名角色的关键设定，比写得少更让人出戏。

**⑤ 顺带修了测试**：加上维基检索后，测试里的 `runFullRound` 会真的去请求维基百科并等满 3 秒超时，整套测试从 0.4 秒涨到 16 秒。现在测试统一用 `researchEnabled: false` 绕过网络，耗时回到 0.43 秒。

### 第九轮变更：对话（局）与线性时间线

反馈有两条，合起来其实是同一个判断：

1. 左栏不该是「轮次目录 + 新建轮次」，应该是**整个对话的目录**——切换和新建的是**完全无关的另一条故事线**。
2. 删除轮次没必要：「我直接在我想删除的那一轮的上一轮重跑就行了」。

也就是：**轮次是线性的，不该被当作可独立增删的对象；可切换的是「局」。**

改动：

**① 引入 `Session`**

```ts
interface Session { id: string; title: string; createdAt: string; updatedAt: string }
interface Round { ...; sessionId: string; index: number }   // index 在 session 内从 1 开始
```

- 第一次发送会**自动创建**一条对话，不需要先点「新建」
- 左栏换成 `SessionList`：新建 / 切换 / 改名 / 删除整个对话
- `BoardView` 只渲染当前对话的轮次

**② 对话自动命名**：第一轮跑完后，用场景构建给出的 `place` 命名（「城南茶馆」），没有就用情境或输入前 14 字。`autoTitleSession` 只在标题还是默认值时才生效，你手改过就不会被覆盖。

**③ 轮级重演取代「删除轮次」**：每一轮的分隔线上有「从这一轮重演」——

```
replayFromRound(roundId):
  1. 确认（如果后面还有轮次）
  2. truncateAfterRound(roundId)   // 同对话内 index 更大的轮次、步骤、账本一起清掉
  3. rerunFrom(该轮的第一个步骤)
```

这样「删掉第 3 轮」的操作就是「在第 2 轮点重演」，和用户脑子里的时间线一致。`truncateAfterRound` 只清理同一条故事线内、序号更大的轮次，不会误伤另一条对话。

**③-b 整段原文可编辑**：光能改拆解后的片段不够 —— 用户想的是"我把这句话重写一遍"，而不是"我把这条 speech 改成 action"。

「你的输入」块右上角加了 **「编辑原文」**：整段重写 → 「保存并重新生成」：

```ts
regenerateRoundFromInput(roundId, newInput):
  1. truncateAfterRound(roundId)      // 丢弃这一轮之后的轮次
  2. updateRoundInput(roundId, text)  // 换上新写的原文
  3. clearRoundSteps(roundId)         // 清掉这一轮已有的步骤
  4. runRoundFor(roundId)             // 整轮重跑
```

**第 3 步是关键，也是它和「重演」的区别**：改了原文，出场角色可能就变了；如果只做 `rerunFrom`，步骤树还是旧的那一套（`context` / `roleplay` 步骤的数量是按旧角色建的），新角色根本不会有反应。所以必须清掉整棵步骤树重来。

三种改法的粒度：

| 操作 | 影响范围 | 代价 |
|---|---|---|
| 改拆解里的单个片段 | 只让下游步骤过期 | 最轻，其余分支复用 |
| 「从这一轮重演」（原文不变） | 该轮全部步骤 | 中 |
| 「编辑原文」+ 重新生成 | 该轮全部步骤 + **丢弃后续所有轮次** | 最重 |

**③-c 去掉确认弹窗，改成可撤销**：这几个操作会被反复用（调一句话、重演一段），每次弹窗很烦。现在全部直接执行，代价是必须在顶栏给一个后悔药：

```ts
saveUndo(label)   // 破坏性操作前调用，记下当时的 sessions / rounds / steps / ledger
undoLast()        // 整份恢复，恢复后快照失效
```

覆盖三处：`replayFromRound`、`regenerateRoundFromInput`、删除对话。快照只在内存里、不持久化——刷新页面后自然失效，不会攒下一堆历史状态。

### 第十轮变更：每轮独立的成人向分级

需求：加一个 R18 模式，但**每次提交时单独勾选**；勾了以后向 AI 提示「想往 R18 方向发展」，剧情仍不能脱离人设，只是 AI 能控制的那部分往这个方向走。

两个设计决定：

**① 分级挂在轮次上，不是全局设置。** `Round.rating: 'general' | 'r18'`（可选字段，旧数据按 general 处理）。理由是同一个故事里不同桥段的尺度不一样，做成全局开关一定会有人忘记关。发送后输入框的勾选归零，强制每轮主动选。想改某一轮，在「编辑原文」里改。

**② 分级只影响提示词，不影响流水线结构。** 所有确定性计算（拆解、阵容、编排、记忆）保持不变，只在三个「需要发挥」的地方加一段：

| 阶段 | 放开了什么 | 边界 |
|---|---|---|
| S2 场景构建 | 氛围可以更私密（光线、距离、体温、沉默的质感） | **不许改变人物处境与关系** |
| S2b 你的外化 | 线索可以更直白（呼吸、体温、视线停留的位置） | **泄漏程度仍由人设决定**，藏得住事的人照样藏得住 |
| S5 角色反应 | 距离、触碰、语气、身体反应 | **三条底线 + 不许脱离人设** |

角色提示词里的三条底线是重点。缺了它们，模型很容易理解成「勾了 R18 就可以换个人演」：

1. **性格不能变。** 一个克制的人在这种场景里依然是克制的，只是克制的内容变了；爱开玩笑的人依然会开玩笑。
2. **推进必须是「你会做的事」。** 关系没到那一步就不跳过去 —— 该犹豫的还是犹豫，该试探的还是试探。
3. **不要一步到位。** 节奏由此刻的关系与情境决定，不由分级决定。

界面上，开了 R18 的轮次会在分隔线上显示一个红色标记，回看时一眼能看出哪几轮是。

**④ 记忆与角色库跟着一起回退**：因为它们本来就是从步骤图派生的（`getMemories` / `getCastLibrary`），被 truncate 掉的轮次连同它们的记忆一起消失，不需要额外补偿逻辑。

**⑤ 补充：对话之间必须完全隔离。**

第一版漏了这一点 —— `getCastLibrary(steps)` 与 `getMemories(steps)` 是**从整个工作区的步骤派生**的，新开的对话会直接认领上一场戏的角色卡、并且继承它的记忆。这跟"完全无关的另一条故事线"是矛盾的。

修法是给这两个函数加 `roundIds` 过滤，调用时传入**当前对话的轮次集合**：

```ts
function sessionRoundIds(ctx: PipelineContext): Set<string> | undefined {
  if (!ctx.rounds?.length) return undefined          // 拿不到列表就不隔离（向后兼容）
  return new Set(ctx.rounds.filter(r => r.sessionId === ctx.round.sessionId).map(r => r.id))
}
```

三处都要挂上：

| 位置 | 作用 |
|---|---|
| S3 阵容解析的 `library` | 新对话不会复用旧对话的角色卡，会重新建卡并重新查资料 |
| S4 上下文分配的 `memories` | 新对话的角色不会记得旧对话的事 |
| `findPreviousScene` | 新对话的场面构建不会接上旧对话的「上一幕」 |

右栏的「角色与记忆」「步骤历史」同样只显示当前对话。

**⑥ 旧数据迁移**：`store/migrate.ts` 在启动时把没有 `sessionId` 的旧轮次收拢进一条「早先的对话」，一次性写回。

### 实现中偏离设计的两处

1. **不用 Tailwind，改手写 CSS**（`src/index.css`）：少一个构建依赖、少一处版本兼容风险，面板密集的界面用 CSS 变量 + 语义类名同样可控。
2. **包管理器用 npm 而非 pnpm**：本机 `pnpm` 是 corepack 代理，需要写 `~/.cache/node/corepack`，在当前沙箱下被拒绝；且 `pnpm init` 写入的 `packageManager: pnpm@12.4.1` 会让 npm 直接拒绝执行。用 npm + 工作区内的 cache 目录可正常运行。

### 第十一轮变更：提示词结构为「缓存命中」重排

**问题**：一轮里每个角色都是一次独立的 API 请求。原来的角色提示词把角色卡直接塞进 `system`，
于是同一轮里 N 个角色的 `system` 各不相同 —— 服务端的提示词前缀缓存（DeepSeek / OpenAI 的
prompt caching）一个都命中不了；而 `system` + 前文回顾常常是整条提示词里最长的部分，
角色越多、剧情越长，重复计费越狠。

**做法**：把「所有角色共同的部分」全部提到最前面，变成一条与角色无关的稳定前缀。

| 位置 | 内容 | 谁共享 |
|---|---|---|
| `system` | 通用指令（**纯静态常量，一个字节都不变**） | 同一个账号下的所有请求：跨角色、跨轮次、跨分级、跨对话 |
| `user` 前半段 | 共享背景：故事名、时间地点、pc 概况、在场名单、前文回顾 | 同一轮的所有角色 |
| 分隔线 | `━━━ 以下只属于「你」━━━` | —— |
| `user` 中段 | 角色卡、能力、感知、标志性特征、语句示例、原作锚点、底线、记忆、眼前环境、自己的心理、额外察觉、实际接收、确定不知道的事、任务 | 只有这个角色自己 |
| `user` 末尾 | 本轮设定：自由度 + 成人向段落 | 同一轮的所有角色 |

把「会变的东西」排到末尾是这条设计的关键。`system` 做成静态常量之后，用户第一次请求
就把这段缓存住了；之后再怎么换角色、换分级、**把 R18 复选框来回勾**，也只是末尾那一小段
变化，前面整段照旧命中。自由度与分级放末尾还顺手修好了一件事 —— R18 段落里
「不违背上面人设」原来指的是它**下面**才出现的角色卡，现在确实在上面了。

三个附带修正：

1. **在场名单不再按视角裁剪**。原来写的是「场上还有：{除我以外的人}」，每个角色看到的名字集合不同，
   共享前缀就断在那一行。现在统一写成「在场的人：我、林砚、阿七」—— 名单本身是公开信息，
   不构成泄漏，但保住了整个前缀。
2. **老数据容错**：`ContextBundle.recap` 是后加的字段，旧工作区里存的上下文包没有它，
   渲染时按空串处理，不会把历史存档炸掉。
3. **`SEPARATOR` 导出**，测试和后续 UI（比如「这个角色实际收到了什么」面板）可以复用同一条分隔线。

新增 `tests/cache.spec.ts` 七条断言，把这个约定钉死：

- 同一轮里所有角色的 `system` 完全相同；
- `system` 里不含任何角色专属字符串（角色名、性格、前文回顾都不行）；
- `system` 只由项目设置决定，跨轮也逐字节一致；
- `system` 是静态常量：换自由度、换分级都逐字节不变，变的只能是 `user`；
- 不同角色的 `user` 在分隔线之前逐字节相同（含前文回顾与环境）；
- 共享段在前、专属段在后（前缀越长越省）；
- 分隔线之后必须逐字节不同，且各自含自己的角色名。

最后一条尤其重要：它保证「为了缓存而把角色专属内容挪到前面」这类退步会被测试拦住。

### 第十二轮变更：往事逐轮累加，「同一个角色」跨轮命中缓存

**上一轮做错的地方**：我当时的判断是「同一轮里所有角色共享一段前缀最省」，
于是把共享背景排在最前、角色卡排在后面。这个方向是错的 —— 一轮里的角色就那么几个，
省下来的是常数；真正值钱的是**同一个角色跨轮次**：第 K+1 轮发出去的提示词，
应当以第 K 轮发出去的提示词为前缀，多出来的只有最后那一段。

**顺带暴露的老问题**：前文回顾一直是「只看最近两轮」（`roundsBack = 2`，
再套一个 2400 字符的滑动窗口）。省 token 是真的，但代价是角色会忘记他三轮前
说过的话 —— 一致性先坏在这里，而一致性是这个项目唯一不能让步的东西。

**新结构**（`buildRoleplayMessages`）：

```
system   通用指令（静态常量，永不变化）
user
  ├ 长期设定        角色卡：你是谁、你会什么、你的底线 —— 同一个角色每轮逐字节相同
  ├ 往事            ── 第 1 轮 ── … ── 第 2 轮 ── …（一轮一段，一路累加，永不重写）
  ├ 这一轮          ── 第 K 轮 ── 接在同一串编号后面：场面 + 环境 + 你实际接收到的事
  ├ 本轮设定        自由度 + 成人向
  └ 你的任务
```

关键在于**往事与当前轮共用同一个渲染函数**（`renderRoundBody`），
而且当前这一轮的正文只依赖**它自己的那些已经固定下来的步骤**：
事后重放时逐字节可复现，所以第 K 轮的「这一轮」到了第 K+1 轮会原样变成
「第 K 轮」那一段。于是：

```
第 K 轮:    [设定][往事 1..K-1][第 K 轮正文][本轮设定][任务]
第 K+1 轮:  [设定][往事 1..K-1][第 K 轮正文 + （你当时在想：…）][第 K+1 轮正文][本轮设定][任务]
                                └────────── 到此处为止，逐字节前缀 ──────────┘
```

**实现要点**：

| 位置 | 作用 |
|---|---|
| `engine/history.ts` | `collectHistory()` 从**已完成的步骤**里重建该角色经历过的每一轮；`renderRoundBody` / `renderHistoryRound` 被往事与当前轮共用 |
| `PerceptionEntry` 的漏看/听岔 | 往事重建时按文本对回候选池：判为 `missed` 的整块删掉，判为 `distorted` 的换成分发层给出的版本 —— **过去的轮次也照样受信息隔离约束** |
| AI 之间的言行 | 同一轮里 AI 是并发演出的，互相看不见；到了下一轮它们成为既成事实，按「默认所有人都收到了」的协议一律给他 |
| `HISTORY_MAX_CHARS` | 24000 字符的安全上限。超了从**最早**的一轮开始丢并注明「更早的 N 轮已经太长」；压缩策略留到真正撞上再说 |
| `buildRecap()` | 拆解 / 场面 / 阵容三个阶段用的「共享版前文」同样改成一路累加（它们要判的是"这句话在说谁"，需要完整剧情，不做视角过滤） |
| `ContextBundle.history` | 结构化存每一轮，UI 的「他收到了什么」面板把它逐轮摊开 |

**两个被这一步顺带修掉的 bug**：

1. **pc 台词被套了两层壳**。候选池为了让「信息分发」那个模型看懂是谁在说话，
   把 pc 那一侧写成 `你：「…」`；而 `buildPerceived` 直接把它当成台词原文去渲染，
   于是提示词里出现 `我：「你：「…」」`。现在在消费侧把壳剥掉。
2. **往事里丢了「正在发生什么」**。编排结果里只有开场画面，没有 `sceneSetup.situation`，
   所以回看往事时那一句是缺的（而当时发出去的时候有），前缀对不上。
   现在按同一顺序把 `opening` + `situation` 补回环境最前面，并对编排里的开场画面去重。

**记忆摘要怎么办**：`recalled`（每轮一条 `summary`）不再单独发 —— 往事里已经有全文了，
再发一遍纯属重复计费。它仍然被算出来、仍然在面板里可看，留作将来压缩的原料：
真撞上上限时，最早的那些轮次可以只留摘要、丢掉全文。

新增/改写的测试：

- `tests/cache.spec.ts`：`system` 是静态常量；**第 K 轮发出去的内容整体出现在第 K+1 轮的开头**；
  往事逐轮累加且顺序正确；往事里带着他自己当时的心理；会变的东西排在最后；
  外加一个**真跑三轮**的集成用例，断言第 3 轮的提示词里第 1、2 轮的原话都还在，
  且第 2 轮的提示词是第 3 轮的前缀。
- `tests/render.spec.ts`：上下文面板把往事逐轮摊开；还没有往事时明说这是第一轮。
- `tests/perception.spec.ts`：断言改成剥壳之后的原文（原先断言的其实是那个双层壳的 bug）。

### 第十三轮变更：角色得有内生驱动力，世界得自己往前走

**问题**（用户实测）：遇到狼群，金刚狼让你别动；你写「我听着他的吩咐不动」之后，
**所有角色都转过头来继续对你说话 / 吩咐 / 看你的表现**，狼群不见了。

诊断下来是三个具体的刹车，都在提示词里：

1. **角色被写成了纯反应器，而且被逼着开口。**
   `roleplay` 的收尾是「对**眼前这一幕**做出你的反应」，硬性格式第 4 条是
   「你**至少要说一句话**」。于是不管局面多紧张，每个角色都必须产出一条对着 pc 的表现。
2. **没有任何行动者负责「世界」。** 场景构建器的定位是「把用户给的素材变成
   **一个可以立刻开演的场面**」——输入是用户写了什么，输出是布景和在场名单。
   环境只在编排里当静态布景，永远不会自己变化。「狼群扑上来」这件事
   必须等用户写出来，否则它不存在。
3. **角色只有性格，没有目标。** 卡里是 `summary / speechStyle / temperament /
   habits / boundaries`，全是"他是个什么样的人"。驱动动作的是 objective，
   不是性格 —— 没有目标，模型只能对着用户的输入做姿态。

**做法**：

**① 新增一个不代表任何角色的行动者「局面」（S3c）**

每轮一次调用（不是每个角色一次），排在阵容解析之后、信息分发之前。
它只回答一个问题：**如果所有人都不作为，接下来会发生什么？**

| 字段 | 含义 |
|---|---|
| `pressure` | 此刻正在逼近的东西，一句话 |
| `escalation` | 如果没有任何人干预，下一步会发生什么 |
| `events` | 这一轮客观发生的事（0~3 条），进时间线、也进信息分发 |

它的 SYSTEM 里写死了几条边界：不替任何人做决定、不解决冲突（只把门推开，不把门关上）、
不推翻用户刚写的东西、大多数轮次只推进一点点，压力积累够了才爆发。

三个接进现有骨架的地方：
- **进时间线**：编排里排在用户内容之后、角色反应之前，用新的 `world` 块类型，
  主看板上单独成型（栗色竖线 + 「局面」徽章），一眼能看出"这不是谁说的话"。
- **进信息分发**：局面事件一样要过感知判定 —— 背对着的人就是没看见。
- **进往事**：`HistoryRound` 存了那一轮的 `pressure` / `escalation`，回看时
  「当时的局面」和「当时的下一步」都还在，前缀对齐也保住了。

**② 角色卡新增「他想要什么」（`persona.drive`）**

阵容解析时一起产出，要求写具体、可执行、有对象。提示词里渲染成【你想要什么】，
并附一句「每一轮你都在朝它走，哪怕用户什么都没做」。
没写明时不是留空，而是明确要求模型**从处境与性格里推断出一个目标并朝它行动**。

**③ 角色提示词去掉"必须开口"**

- 删掉「你至少要说一句话」，`beats` 现在**可以为空**。
- 新增【最重要的一条：你不是在等用户】：世界在动，你有自己的事要做；
  用户没给你新信息、也没在跟你互动时，你完全可以**不和他说话**。
- 沉默不再是需要辩解的例外，而是表演的一部分（`silentReason` 保留）。

**④ 顺手把默认的「不围着你转」写进第一条**

`drives`（在场的人各自想要什么）也会给「局面」看 —— 这样施加的压力能压在各人的目标上，
而不是漫无目的地制造紧张。

**新增测试** `tests/situation.spec.ts`（8 条）：局面事件进候选池且编号连续、
进时间线且排在用户内容之后 / 角色反应之前、模型不可用时降级并沿用上一轮压力、
drive 进提示词、没写 drive 时要求模型自己推断、局面与 escalation 进提示词、
`system` 里不再有「至少要说一句话」。

**还没做的**：局面的压力线目前只跨轮携带一句话，没有数值化的「张力」；
角色之间也没有"我要阻止他"这类**相互目标**。等遇到再说。

### 第十四轮变更：往事只装他自己经历过的

**问题**（用户实测）：上一轮的「往事逐轮累加」把记忆写成了**上帝视角的剧本回顾**。

两个漏洞：

1. **不在场的轮次照累不误。** `collectHistory` 只是把历史轮次按顺序拼起来，
   完全没看这个角色当时在不在场。一个第 5 轮才第一次出场的角色，
   一建卡往事里就装着他前 4 轮根本不在场的全部剧情。
2. **别人的言行无条件塞进去。** 往事是从 `compose` 重建的 —— 那是完整剧本，
   包含所有角色的台词和动作。整条链路上只有一个过滤：pc 那一侧按感知判定剔一遍。
   **其他 AI 角色的言行从头到尾没经过任何判定**，全给了。

根子上是我上一轮图省事：为了让角色别忘记自己说过什么，直接拿了编排结果。

**做法**：

**① 在场判定以「那一轮的场面」为准**

`sceneSetup.present` 里有没有他（名字或别名）。不用"有没有跑过给他组装上下文的步骤"——
那会被重跑和清空影响，而场面是已经定下来的事实。

**② 内容只取「那一轮真正发给他的那一份上下文」**

不再从 `compose` 重建，改为读那一轮的 **context 步骤产物**。那份东西里已经包含了
当时的感知判定（谁的话他听到了、什么他漏看了），也**只有他该知道的东西** ——
别人的言行从来不在里面，所以不可能混进他的记忆。

唯一要补的是**他自己当时说的话、做的事**（从那一轮的 roleplay 步骤取）：
那是一定知道的，而它不在感知候选池里，因为 AI 的反应是并发生成的。

**③ 不在场的轮次只留一行**

```
── 第 2 轮 ~ 第 4 轮：你不在这里 ──
```

内容一个字都不给，但保留时间感（他知道中间发生过事，只是不知道是什么）。
连续的几轮会合并成一行。往事说明里也补了一句「标着『你不在这里』的那几轮你不在场，
那段时间发生了什么你并不知道」。

**④ 顺带修掉一个双重前缀**

`buildPerceived` 剥壳时只处理了 pc 那一侧，导致非 pc 的候选带着 `林砚：` 前缀
又被渲染器加一遍，往事里出现「你：林砚：林砚已经坐在靠里的位置」这种双重前缀。
现在按 `candidate.from` 剥（pc 那一侧的壳是「你：」）。

**代价（已知）**：同一场里两个 AI 互相不记得对方上一轮说过什么 —— 因为 AI 的言行
本来就在感知候选池之外（同一轮里 AI 是并发演出的，互相看不见）。
要补这个洞需要单独做「跨轮分发」：把上一轮的 AI 言行也交给分发层判定谁注意到了。
这次的取舍是**宁可记少，不可记错**。

**新增测试** `tests/history.spec.ts`（5 条）：不在场的轮次内容一个字都不给、
连续几轮合并成一行、别名也算在场、别人的 AI 言行不进往事而他自己说的做的不丢、
第一次出场的角色往事里全是「你不在场」。`tests/render.spec.ts` 补一条面板断言。

### 第十五轮变更：角色挨个反应，顺序由「局面」定

**问题**（用户实测）：上一轮把角色的记忆修对了，但演绎方式还是错的 ——
**所有角色是并发跑的，互相看不见**。于是出现一个荒谬的结果：

> 遇到狼群，金刚狼先说「别动」，阿七接着说「我去引开它们」——
> 但金刚狼根本不知道阿七说过这句话，因为他们是同时生成的。

时间顺序上 A 先说了话，B 就在旁边，他当然听得见。并发是我一开始就默认的前提，
它把"同一轮"当成了一个不可分割的瞬间，而实际上**一轮之内也是有先后的**。

**做法**：一轮之内改成**串行演绎**。

```
局面（导演）：世界怎么变 + 这一轮谁先动
      ↓
信息分发：把「你写的 + 世界发生的」按各人视角分好
      ↓
角色 1 的上下文 → 角色 1 的反应
      ↓（把角色 1 说的话做的事并进去）
角色 2 的上下文 → 角色 2 的反应
      ↓（把角色 2 的并进去）
角色 3 …
      ↓
编排（按时间顺序接起来）
```

实现上只改了一处依赖关系：`context_i` 声明依赖 `roleplay_0..i-1`。
调度器本来就是按依赖分层的，于是**依赖链自然把并发变成了串行**，
不需要为它写一套新的执行器。副产物是 UI 上角色卡片会一个一个出现，
而不是齐刷刷一起冒出来 —— 反而更像真人挨个反应。

**谁先谁后**：由「局面」决定。它现在实际上就是这一场戏的**导演**，
提示词里加了第二个职责：

- 谁最可能先做出反应？被点到名的、离危险最近的、性子最急的、目标被直接挡住的，排前面。
- 谁只会在别人动完之后才反应？观望的、被动的、地位低的，排后面。
- 顺序不是"谁话多谁先"：先动的人也可能是先动手的那个，甚至一句话都不说。
- 必须把需要反应的人全排进去，一个不多一个不少。

引擎只做兜底（`orderActors`）：名单里多出来的名字丢掉，漏掉的人按阵容顺序补在最后；
局面整个降级（调用失败）时，直接退回阵容顺序。

**往事跟着变**：既然一轮之内的先后是真实的，往事也必须按这个顺序存 ——
「他之前发生的事（已在他的上下文里）→ 他自己 → 他之后的人」。
于是他**当时还没听到的**那些（排在他后面的人说的话），到他下一轮回看时就成了往事。
这正是「B 说的话只记录，下一轮作为『之前发生了什么』附上」的落点。

**代价**：延迟从"最慢的那个角色"变成"所有角色之和"。三个角色就是三段串行等待。
这个代价是买正确性 —— 并发版本省下来的时间，换来的是角色互相装聋作哑。

**新增测试** `tests/serial.spec.ts`（5 条）：后开口的人看得到先开口的人刚说了什么、
顺序由局面说了算（把 order 反过来，能看到的就换了人）、确确实实是串行执行、
导演漏排的人会被补在最后、下一轮时先开口的人也知道了后开口的人上一轮说了什么。

### 第十六轮变更：僵局时，导演有权点名角色上场

**问题**（用户实测 + 纠正）：角色没有内生驱动力这一轮补上了「局面」（导演），
但导演的规则里有一条写得太死：**「不要替任何人做决定」**。于是出现一个新的死锁 ——

> 用户写的人设就是"什么都不会做"的人（怯懦、犹豫、被动、在装死）。
> 他不动，角色们又各有各的理由等着。谁都不先动，这出戏死在原地。

**第一次修错了方向**：我一开始让导演**替用户**做一个"不承载意志的身体反应"
（缩了一下、被撞得让了半步），还给它加了 `subject: pc` 的事件字段。
用户立刻纠正：**用户本身的言行绝对不能替他做决定** —— 那条红线是这个项目的根。
用户不动，该动的是**角色**，不是用户。

**正确的做法：导演点名。**

僵局时，导演点名一个最该动的人，给他一句**推力**，写进他的上下文：

```json
"nudges": [
  {
    "who": "金刚狼",
    "push": "狼群已经贴到三步之内，站在你身后那个人会是第一个被扑倒的。",
    "act": "他动了 —— 第一头狼刚扑上来就被他按进了泥里。"
  }
]
```

被点名的人这一轮会收到一条【导演指令】：

> 导演要你在这一轮里做到这个：
> 他动了 —— 第一头狼刚扑上来就被他按进了泥里。
>
> 他的理由：狼群已经贴到三步之内，站在你身后那个人会是第一个被扑倒的。
>
> 这件事**必须发生**，但**怎么发生由你演** —— 用你的动作、你的台词、你的节奏
> 把它落实下来。不要复述上面那句话，也不要让这件事显得像是别人替你做的。

**第二版又修窄了一次**：我一开始只让导演说"现在不是等的时候，动什么由你定"。
用户指出这仍然不对 —— **导演通读台本，他和演员有同样的权限**，
他完全可以说「金刚狼动手了」，这就是剧情层面的指令。差别只在于：
**只有僵局的时候他才说。**

所以 nudge 有两段：

| 字段 | 含义 |
|---|---|
| `push` | 为什么现在必须动（砸在他的目标或处境上） |
| `act` | 导演指定的剧情动作（可以不给）。「他动了 —— 第一头狼刚扑上来就被他按进了泥里。」 |

**三条边界**（都写进提示词了）：

1. 指令只到**剧情**这一层：他做了什么。**不写台词、不写心理、不写表情和语气的细节** ——
   那些是演员的活，被点名的人收到指令后会自己演出来。导演写得越细，角色越像提线木偶。
2. **用户扮演的角色永远不在点名范围内。** 他不接戏，就只能由角色去接。
   引擎侧也做了兜底：`normalizeNudges` 直接把 pc 从名单里剔掉。
3. 不是每轮都点，**只有僵局才点**，一轮最多一两个人。

**僵局的判断标准**（写进提示词）：

- 用户这一轮没有推动任何事（只是看着、等着、说了句不痛不痒的话）
- 角色的反应也只是姿态，局面和上一轮没有实质区别
- 而且**上一轮也是这样** —— 连着两轮没人往前走

**实现链路**：`SituationState.nudges` → pipeline 按名字取出属于这个人的那条 →
`ContextBundle.push` → roleplay 提示词渲染成【导演点名】。
没被点名的人拿不到（`push` 为 undefined），所以不会所有人一起被催。

**新增测试**：`tests/situation.spec.ts` 补两条（被点名的人收到、没被点名的收不到；
提示词里写死了"永远不点用户"与 `nudges` 字段）；
`tests/serial.spec.ts` 补一条端到端 —— 真跑一轮，断言林砚的上下文里有推力、
阿七的没有、且只有林砚的提示词里出现【导演点名】。

### 第十七轮变更：「什么都不做」是一个按钮，不是空输入

**问题**（用户提出）：前面几轮一直在补"僵局时谁该动"，但用户手上其实缺一个**动作**：
他有时候就是想什么都不做（人设如此，或者想看看别人怎么反应）。
在那之前只有两条路 —— 要么硬写一句废话推进一下，要么发一句"我站着不动"。

**做法**：输入框旁边多一个按钮 **「什么都不做」**。

它不是"空输入"，是一次**主动交棒**：

- `Round.idle = true`，原文写死成 `（这一轮我什么都没做。）`。
  之所以要非空，是因为整条流水线得有素材可拆；这句话一看就知道是交棒而不是台词。
- 导演收到的**不是**那句占位文本，而是一条明确的信号：

  > 用户主动交棒：这一轮他什么都没做。把主动权接过来。

- 提示词里给这一轮加了强刺激（比普通的僵局判断更硬）：

  > 这是给你的强刺激，不是让你也停下来。
  > - 世界必须往前走，而且要比平时**大一步**。
  > - **必须点名**，而且要给 `act`（不能只给 `push`）—— 让某个人真正动起来。
  > - 如果这一轮最后什么都没发生，那就是你失职。

**为什么单独做成一轮而不是"跳过"**：跳过的话时间线就断了，而"他什么都没做"
本身**是一段真实的剧情** —— 对方会怎么解读你的沉默，是很多戏的关键。
所以它照样跑完整条流水线，照样进往事、进记忆、进别人的感知。

**新增测试**：`tests/situation.spec.ts` 一条（交棒轮的 system 里必须有强刺激、
必须要求给 act、且占位文本不会被当成台词递给导演）；
`tests/serial.spec.ts` 一条端到端（真跑一轮，断言 situation 的提示词里是交棒信号
而不是那句占位文本）。

### 第十八轮变更：把「时间跳跃补全」接上（原来是个死开关）

**发现**：设置面板里有一个「时间跳跃补全」开关，说明写着"自动推断这段时间里
每个角色各自经历了什么"。但引擎里**零引用** —— `interludeFill` 只在设置界面和
默认值里出现，`timeSkip` 被场景构建解析出来之后也没有人用。
换句话说，那是个勾了也没用的死开关。

**用户的说明**：主角永远是**在场**的，"主角不在场"这种情况不存在；
唯一存在的是「他在场但选择什么都不做」（第十七轮的按钮）。
而剧情跳过的那段时间，**应该在他下一次出场时补全** —— 这正是那个开关该干的事。

**做法**：

**① 场景构建负责补全**（它本来就是"把概要展开成场面"的那一步）

输出多一个字段：

```json
"interlude": {
  "summary": "这三天茶馆照常开着，只是靠里那桌一直空着。",
  "each": [
    { "who": "林砚", "what": "他每天照常开门，把那半盏茶的位置留着没动。" },
    { "who": "阿七", "what": "他把后院的柴劈完了，谁也没提那天晚上的事。" }
  ]
}
```

提示词里写死了三条：顺着已有设定走、**不要凭空加新角色/新事件/新矛盾**
（填的是"他们照常过日子"那一层，不是新开一条剧情线）、没有时间跳跃就留空。
开关关掉时，提示词变成明确的"不要补全"，interlude 一律留空。

**② 分发遵守视角**

`summary` 是所有人都看得见的那层，进每个人的上下文；
`each` 里**只有属于他自己的那条**给他。别人的那三天他并不知道
（`buildContextBundle` 按 `card.name` 取，取不到就是空）。

**③ 进轮块，也进往事**

补全渲染成轮块开头的两行：

```
── 第 2 轮 · 三天后 · 城南茶馆 ──

【这之前】这三天茶馆照常开着，只是靠里那桌一直空着。
【这段时间你在做什么】他每天照常开门，把那半盏茶的位置留着没动。
```

因为它在轮块里，`HistoryRound` 也存了这两个字段 —— 回看时接得上，
而且当前轮与往事的逐字节前缀对齐也保住了。
场景卡片上也会显示补全的内容，你能看到引擎替你填了什么。

**新增测试** `tests/interlude.spec.ts`（4 条）：开关打开才要求补全、关掉时明确不许补；
共享那段所有人都看得到而各自那条只给本人；补全写进角色这一轮的提示词；
往事里也带着那段空白期。

### 第十九轮变更：角色要回应的是局势，不是用户

**问题**（用户实测）：点了「什么都不做」之后，导演确实点名了，但角色拿到任务之后
**还是回过头来指挥用户** —— 遇到狼群，金刚狼不去交手，反而继续对用户说
「别动」「待在我身后」。用户的原话：*他老是指挥我干嘛？*

**根因是一个结构性偏置**：角色看到的东西里，pc 的言行排在
【你实际接收到的事（按时间顺序）】里，是一条**事件**；
而局面发生的事（狼扑上来）被塞进【你眼前的环境】，是**背景板**。
在模型眼里，时间线上只有用户在动，狼只是布景 —— 它当然会对着用户做反应。

三条修法，从结构到措辞：

**① 局面事件进时间线**（这是根子上的那条）

`PerceivedEvent` 多一个 `kind: 'event'`，代表**没有人在做它**的事：

```
【你实际接收到的事（按时间顺序）】
1. 我：我听着他的吩咐不动。
2. （我的样子）……
3. 〔发生〕最前面那两头狼伏低了身子。
4. 〔发生〕第一头狼扑了上来。
```

它不再是背景，而是和 pc 的言行并列的、正在发生的事。信息分发照样管它
（背对着的人就是没看见）—— 候选池里它用 `event` 这个 kind，
提示词里译作「正在发生的事」。

**② 提示词从「回应这一步」改成「回应局势」**

- SYSTEM 的第一条从「你不是在等用户」改成「**你要回应的是局势，不是用户**」，
  并写死一句：去处理那些事的时候，**你完全可以整轮不对用户说一个字**，
  不用向他解释、交代、请示。
- 尤其点名了那个坏习惯：*当你发现自己想对用户说「别动」「待在我身后」这类话的时候，
  先问一句 —— 这句话现在真的有用吗？如果真正该做的是动手，那就动手。*
- 收尾的任务说明也从「对眼前这一幕做出你的反应」改成「决定你这一轮做什么」，
  并补上"要回应的是整个局势，不是用户一个人"。

**③ 【导演指令】补了一句**：这件事多半和用户没有关系，直接去做，
不需要先跟他说一声。

**④ 第一版把交棒告诉了角色 —— 用户指出那是元信息，只有导演该知道**

我一开始给 `ContextBundle` 加了 `pcIdle`，让角色知道"用户把这一轮交出来了"，
提示词里还写了一句"那不是让你去搭话的信号"。**用户直接指出这不对**：

> 角色不应该知道"我把这一棒交出来了"。这是 meta 信息，只有导演知道，
> 所以应该由导演**更加深入地决定和指挥**。

这个批评是对的，而且比 `pcIdle` 那一处更深 —— **交棒轮的原文本身就是元信息**：
`IDLE_INPUT`（「这一轮我什么都没做。」）会被拆解成片段、进候选池，
角色会在时间线上读到「我：（这一轮我什么都没做。）」。那不是一个角色能观察到的事实，
那是一句**关于轮次的陈述**。

所以现在的边界是：

| 谁 | 知道什么 |
|---|---|
| 导演 | 全部 —— 包括"用户主动交棒了"这件事 |
| 角色 | 只知道**他没有动**这个可以被观察的事实，不知道有"交棒"这回事 |

实现上：`pcIdle` 整个撤掉；交棒轮的 segments 在 perceive 与 context 两处
都不进候选池（`ctx.round.idle ? [] : segments`）；导演的提示词里写死一句
**「你不能把这个信息转达给任何人」**（不要说"他交给你了""他决定不动"这类话，
那是元信息，会让他们开始对着空气演戏）。

**导演在交棒轮要更深入地介入**（这也是用户要求的"更加深入地决定和指挥"）：

- 世界往前走**一大步**：events 至少一条，而且要能真正改变局面
  （不是"风吹了一下"，是"门被撞开了"）
- **必须点名，而且必须给 act**，且 act 要具体到发生了什么
- **允许点最多三个人**（非交棒轮是最多两个）—— 用户不推，这一轮就得靠他们撑起来
- 不要写成一段平静的过渡：用户交棒不是让你喘口气，是让你替他推

**新增测试** `tests/agency.spec.ts`（6 条）：局面事件是「发生的事」而不是「眼前的环境」、
它和 pc 的言行在同一条时间线上且排在世界之后、渲染出〔发生〕标记、
角色拿到的提示词里不含任何交棒相关的说法、system 与任务说明都以局势为中心。
`tests/serial.spec.ts` 补一条端到端：交棒轮跑完之后，那句占位原文
没有漏进角色的事件时间线，而场面还在（他不是瞎的）。

### 第二十轮变更：导演要能拦住角色，也要能让冲突落地

**两个问题**（用户实测）：

1. 角色不知道用户在等，所以**每一轮都会本能地回头找用户**。导演既然知道，
   就应该明确拦住他：「你现在的首要任务是你眼前的情形，不要和用户交互。」
2. **导演缺乏脱离场景的能力。** 进了打架的场景就一直在打，永远结束不了。

**第 2 条的根子在我自己的提示词里。** 我写过一条：

> **不要解决冲突。** 你是把门推开的人，不是把门关上的人。
> 你的推进应该让局面更紧、更复杂、更逼人做选择，而不是替他们收场。

这条本意是防止导演替角色收场（把戏写平），但它同时**取消了导演让冲突落地的权限** ——
于是"又一拳"可以无限续下去。**把门推开的人，也得负责把这一幕收掉。**

**做法**：

**① `SituationNudge.noInteract`**

导演点名时可以加 `noInteract: true`，被点名的人收到：

> **这一轮不要跟用户交互。** 你眼前有更要紧的事 —— 别回头跟他说话、别指挥他、
> 别确认他的状态。你的首要任务是眼前这个情形。
> （如果你的人设在这种时候确实会顺带甩半句给他，那可以；但那就只能是顺带的，
> 不能变成对他的交代。）

提示词里写明了什么时候填：眼前有必须处理的事、而用户这一刻没有推进任何东西。
最后那句括号是用户提的 —— 角色卡导演读过，性格上确实会边打架边喊一嗓子，
这种判断交给它，引擎不越权。

**② 收场成为一项独立职责**

「不要解决冲突」那条禁令删掉了，换成一节【收场 —— 你的一项独立职责】：

- 看到最近几轮的节奏里连着两三个 escalate / climax，这一轮就该收：
  有人倒下了、有人跑了、有外力打断了、或者代价已经付清。
- **收场不等于平淡**：把结果落下来（谁赢了、谁受伤了、什么没了、接下来去哪），
  比继续加码更有推进力。
- 已经结束的事不要再翻出来 —— 打完的架不要"突然又冲出来两头狼"。
- 判据：**这一幕的问题有没有被回答？** 没回答就继续，回答了就该翻页。

**③ 导演现在能看到最近三轮的节奏**

`previousSituation` 除了上一轮的 pressure / escalation，还会回传最近三轮的 `pace`，
在提示词里渲染成「escalate → climax → climax（越靠后越近）」。
没有这个，导演根本不知道自己已经加码了几轮 —— 收场也就无从判断。

**新增测试** `tests/situation.spec.ts` 两条：`noInteract` 会渲染成那段明确指令
（不填时不出现）、最近几轮节奏会递给导演且「不要解决冲突」这条已经不在提示词里
（防止它被无意中改回去）。

### 第二十一轮变更：三层定位 —— 用户出点，导演执导，角色演戏

**问题**（用户纠正）：我把自主性给错了人。

前面几轮我一直在给**角色**加自主性 —— 「你要回应的是局势，不是用户」
「你有自己的事要做」「没有人推，他们就会一直聊下去」。同时把**导演**限制成
一个调度员：只在僵局才点名、act 只在僵局给、每轮最多推两个人。

用户把正确的层级说清楚了：

> 用户（我）只作为提出「点」的人，我提出的点一定要被导演采纳。你不能指望我成为
> 一个完整的导演。而导演则具有充分的自主性。而角色则是按照自己的人设，
> 在导演的蓝图里演戏就行。自主性相对较小。

**做法**：把定位整个倒过来。

**① 导演的提示词重写：先讲清三层各自站在哪里**

```
- 用户：他不是导演，他只负责提出「点」…… 他提出的点必须被采纳：
  那是这一轮必须发生的事，你不能忽略、不能绕过、不能让它没有下文。
- 你：这一轮还发生什么、谁做什么、节奏多快、这一幕往哪走 —— 全是你的。
  不要把决定权让出去。用户没写的东西不是"不该发生"，而是该由你来安排。
  如果你也等着，那这出戏就没人管了。
- 角色：他们只负责演。你给出蓝图，他们按自己的人设把细节演出来。
  他们不知道全局，也不该知道 —— 所以需要他们动的时候，要你直接说。
```

**② `nudge` 改名 `direction`，语义从「僵局时点名」变成「导演给角色的任务」**

- **每一轮都可以派**，不是只有僵局才派 —— 安排谁在这一轮做什么是导演的本职。
- 僵局/交棒只是它**必须**派任务的情形。
- 上限统一成三个（原来僵局 2 个、交棒 3 个），并写明"不要把人全点一遍，
  让没被点名的人自己发挥"。
- `push` 从必填变成可选（只要有 `act` 或 `noInteract` 就成立）——
  以前强制要理由，等于逼导演为每个任务编一句解释。

**③ 角色的定位从「自主行动者」改成「演员」**

删掉「你要回应的是局势，不是用户」那一整段（那是给错人的自主性），换成：

> 你在一部戏里扮演一个角色。你**不是编剧**，也不负责推动剧情 —— 那是导演的事。
> 你要做的只有一件事：**按这个人的性格，把分到你的部分演出来。**
> ……你的依据永远是**这个人的性格**。同一件事，不同的人做出来完全不同：
> 有人一句话不说就动手，有人先骂一句，有人愣三秒，有人干脆转身走开。

收尾从「决定你这一轮做什么」改成「**把这一轮演出来**……让熟悉他的人一眼认出这就是他」。
【导演指令】也改名【导演给你的这一轮】。

**④ 不改的部分**

- 红线不动：**用户扮演的角色永远不在任务名单里**，用户写什么就是什么。
- 导演的边界不动：act 只到「剧情」这一层（做了什么），
  怎么说、什么表情、什么节奏仍然是角色的活 —— 那是**表演**的自主性，
  不是**叙事**的自主性，两者不该混为一谈。
- 收场、节奏、压力线、`noInteract`、`recentPaces` 全部保留。

**改动清单**：`SituationNudge` → `SituationDirection`、`nudges` → `directions`、
`ContextBundle.nudge` → `direction`、`normalizeNudges` → `normalizeDirections`
（`push` 可选、上限统一、名字必须对得上在场名单且不能是用户）。

**测试**：`tests/agency.spec.ts` 的第二组从「角色提示词以局势为中心」改成
「角色是演员，导演才是导演」（断言 `不是编剧`、`按这个人的性格，把分到你的部分演出来`、
`不要替导演做决定`）；`tests/situation.spec.ts` 断言导演提示词里
「每一轮都可以派，不是只有僵局才派」和「不要把决定权让出去」都在。

### 第二十二轮变更：把分级也发给导演

**问题**（用户提醒）：`situation`（导演）是 R18 之后才建出来的阶段，
**从来没把分级传给它** —— 而它现在能直接指派角色做什么（`directions.act`），
这个缺口比在别的阶段更大：它既可能白白浪费掉用户明确要的方向，
也可能在没人给它划边界的情况下越界。

**做法**：`rating` 一路传到导演，并给它一份**属于它职责的**成人向说明
（和给演员的是同一套底线，但落到"场面与剧情"这一层）：

```
【本轮分级：成人向】
作为导演，你可以把场面往那边推：
- 让环境更私密：让雨把人困在屋里、把灯拨暗、让外面的声音远下去
- 指派带有身体距离、试探、暗示意味的动作（act 里可以直接写这些）
- 放慢节奏，让这一轮停在细节上，而不是急着推进事件

三条底线，一条都不能破：
1. 人设不变。克制的人在这种场景里依然克制，只是克制的内容变了。
2. 推进必须符合关系阶段。你安排了 act，不等于可以让他们一步跨过关系。
3. 不要替用户做决定。用户扮演的角色永远不在名单里 —— 这条在成人向的场面里
   尤其重要：身体的边界是用户的，不是你的。
```

第 3 条是为导演这一层特意改写的：他能安排**别人**做什么，
但**身体的边界是用户的**，这条在任何分级下都不动。

**新增测试**：`tests/situation.spec.ts` 与 `tests/rating.spec.ts` 各一条 ——
成人向时导演的 system 里必须出现分级段与三条底线，通常向时完全不能出现。

### 第二十三轮变更：派发出去的信息要说成「他自己视角的那句话」

**问题**（用户提出）：用户写「我抬头看了你一眼」，别的角色收到的是什么？

当时的答案是：`我：我抬头看了你一眼` —— **双重「我」**，而且更糟的是，
从角色的视角看，这个「我」指的是**对面那个人**。他读到「我：「你来得比我预想的早。」」
时，完全可能以为是自己说的。被看的人本该读到「他看了我一眼」，
旁观的人本该读到「他看了林砚一眼」。

**做法**：分两层修，引擎管称呼，模型管叙述。

**① 说话人的称呼（引擎，机械、可靠）**

`speakerLabel(from, pcName)`：用户扮演的角色在别人眼里**不是「我」** ——
用户填了真名就用真名，还叫「我」就换成「他」。

**② 我叙述里的人称（模型，需要语义）**

「你」指的是谁、「我」在谁的版本里该变成什么，这需要读懂句子 —— 那是
**信息分发**本来就该干的活（它做的正是"把这一轮转化成每个人各自接收到的版本"）。
所以 `PerceptionEntry` 多一个 `rendered`：

```json
"rendered": [{ "ref": 5, "who": "他", "as": "推门进来，袖子湿了半截。" }]
```

- `who`：这条在他眼里是谁做的
- `as`：内容的转述版本（只管动作本身，主语由 who 提供）
- **没人称代词的信息不用给**（「雨下大了」谁看都一样），保持"只报差异"的协议

**③ 台词是唯一的例外 —— 而且挡了两道**

引号里是用户写的原话，一个字都不能改。所以：
- `normalizeRendered` 里直接丢掉台词条目的 `as`（只允许给 `who`）
- `buildPerceived` 里再挡一次（`item.kind === 'speech' ? undefined : view?.as`）——
  不依赖上游过滤干净，因为"改用户的话"是这个项目的红线

**④ 分发失败时不转述，但称呼照样对**

没有 `rendered` 时退回原文 + `speakerLabel`。文本里可能还留着「我」，
但至少不会让角色以为那是自己。

**效果**（demo 里同一个动作，两个角色看到的）：林砚的上下文里是
`他|推门进来，袖子湿了半截。`，阿七的上下文里是
`林砚|林砚已经坐在靠里的位置…` —— 各自视角，互不串味。

**新增测试** `tests/perception.spec.ts` 一组五条：用户扮演的角色在别人眼里是「他」、
被看的人与旁观者看到不同的说法、**模型硬给台词塞 as 也会被丢掉**、
用户填了真名就用真名、分发失败时退回原文但称呼仍然正确。

### 第二十四轮变更：「快速入戏」+ 成人向下放宽「注意到」的门槛

**两个要求**（用户提出）：

1. 在勾了 R18 的基础上，再加一个**「快速入戏」**：导演更倾向于快速进入剧情，
   旁白的用词更直白、直接，包括「鸡巴」「操」这类粗俗说法。
2. 成人向模式下，**用户的行为细节应该更容易被派发出去、更容易被注意到**。

**① 「快速入戏」是叠在成人向上的一层，不是第三个分级**

数据上它是轮次上的一个布尔字段 `Round.direct`（只在 `rating === 'r18'` 时有意义，
取消 R18 时自动清掉），输入区那个勾选框**只在 R18 勾上时才出现**，
并且和 R18 一样跨刷新保留（`ComposerState`）。改它同样算一次实质修改
（`isRoundDraftDirty` 认这一项），所以"只加勾一个快速入戏"也能重新生成那一轮。

它只影响两件事 —— **多快进入**、**用词多直白**，分别落到导演和角色两个提示词上：

- **导演**：pace 直接给 escalate / climax；act 可以直接写身体上的进展；
  events 更直接（门外没人了、灯灭了）；用词直白不要绕。
- **角色**：该发生的事就让它发生，别再用犹豫、退让、岔开话题拖时间；
  台词直说，脏话粗话都可以用 —— 只要**这个人**在这种时候确实会这么说话。

三条底线一条都没松（性格不变、关系阶段不跳、用户扮演的那个人的边界不归你）。
一个本来不说脏话的人，不会因为勾了它突然满口脏话：**他的直白得是他自己的直白。**

**② 成人向放宽的是「注意到」的门槛，不是空间关系**

`perceive` 现在也收到 `rating`，成人向时多一段：

> 这一轮在场的人会比平时更留意用户：他的呼吸、体温、手指放在哪、视线落在哪、
> 声音有什么变化。所以：默认全收到这条规则不变，但**不要轻易判 missed**……
> 反过来说，别人身上的细节仍然按各自的处境判，不要一并放宽。

「默认全收到、只报偏差」这条协议没动，放宽的只是"差一点就注意到"的那一档。
**空间关系不受影响**：背对着、隔着一条街、在另一个房间，该没看见还是没看见 ——
否则信息隔离就成了摆设。

**新增测试** `tests/rating.spec.ts` 四条：快速入戏两条都齐了才生效（只勾 R18 不出现、
勾了 R18 没勾它也不出现、没勾 R18 更不出现）、导演侧的节奏与用词、
信息分发侧的放宽与空间关系不受影响、以及"只加勾快速入戏也算改动"。
`tests/render.spec.ts` 两条：输入区的勾选框只在 R18 打开时出现。

### 第二十五轮变更：演员也可以推剧情

**问题**（用户纠正）：上一轮我把演员限制得太死了。

我写的是「你**不是编剧**，也不负责推动剧情 —— 那是导演的事」，
把角色压成了导演蓝图的执行器。用户的判断是：

> 演员其实也可以啊。没必要把他限制在导演的框架里。
> 反正他的上一轮动作会作为既定事实发到下一轮导演的输入里。

**这句话里有整个机制的关键：角色有天然的收敛机制。** 他这一轮做了什么，
下一轮会作为既成事实进导演的输入（`buildRecap` 把每一轮的完整编排都带上），
导演必须接着处理。所以放他自己走，戏不会散 —— 不需要用"你不负责推动剧情"
去捆住他，那反而把他变成了提线木偶。

**改动**：

**① 角色的定位从「执行器」改成「合作者」**

删掉"你不是编剧，也不负责推动剧情"，换成：

> 他给的是**骨架，不是笼子**。这个人要做什么、说到哪一步、会不会中途改主意 —— 由你决定。
> **你完全可以推动剧情。** 想走就走，想动手就动手，想问就把话问出来，
> 想把一件压了很久的事摊到桌上就摊开 —— 只要那是这个人真会做的事。
> 你的行动会成为既成事实，下一轮导演会接着处理，不用你先请示谁。

【你不能做什么】的最后一条也跟着改：从"不要替导演做决定。剧情往哪走不是你操心的
事"，改成"不要替**别人**做决定 —— 别人怎么反应是别人的事。但**你自己的决定
不用等谁来批准**"。任务说明也补了"想推动什么就推动什么"。

**② 导演那侧同步：角色不是执行蓝图的工具**

> **角色**：他们**不是执行你蓝图的工具**。他们也会自己推动剧情 —— 那是他们的自主性，
> 也是这出戏好看的地方。但**他们不知道全局**，所以需要他们做某件具体的事时，
> **要你直接说**；不说，他们可能想不到。你给的是骨架，血肉由他们自己长。

**没动的**：导演仍是主控（"不要把决定权让出去"保留）；用户的点必须被采纳；
`noInteract` 仍然有效（那是导演的明确要求）；红线不变 ——
不替别人做决定、不改用户写的话。

**测试**：`tests/agency.spec.ts` 那组从「角色是演员，导演才是导演」改成断言
角色也能推剧情（`骨架，不是笼子`、`你完全可以推动剧情`、`下一轮导演会接着处理`、
`你自己的决定不用等谁来批准`）；`tests/situation.spec.ts` 断言导演提示词里
写的是"他们也会自己推动剧情"。

### 第二十六轮变更：「快速入戏」要把话说明白，并放宽人物的模糊地带

**两个要求**（用户提出）：

1. 快速入戏那部分提示词可以**更直接、更直白、更粗俗**一些 —— 涉及性行为的提示
   写得更明白，让导演知道这里需要干嘛。
2. 勾了快速入戏之后，**角色性格上可以放宽一些**：不是破坏角色性格，
   而是在那些模棱两可的「他到底会不会这么做」上，倾向于成人向解释。

用户还补了一句关键的授权：*「我上面说的『成人向』都不涉及具体的、粗俗的用词，
但是你在具体写提示词的时候如果有必要，必须明确告知各个 AI。」*
—— 也就是说，**不要在提示词里用"更直白"这种模糊说法**，该列词就列词。

**① 两份提示词都重写，把"该写什么"写出来**

导演侧（它负责指派 act）：

> act 要写**明确的性进展**，不是"气氛暧昧了一点"：谁脱了谁的衣服、谁把谁按在哪、
> 手伸进了哪里、口交还是插入、谁在上面 —— 具体到**发生了什么、身体在哪、
> 谁对谁做了什么**。……用词直白。该写操、肏、屌、逼、奶子、射、湿，就写。
> 不要用"两人纠缠""亲密了一番"这类含糊说法把关键的一段糊过去 ——
> 用户勾这个就是为了不糊。

角色侧（它负责演）：

> **身体上的进展要写具体**：他想碰哪里、碰到了什么、身体起了什么反应
> （硬了、湿了、发抖、喘不上气）。……**露骨的词该用就用**：操、肏、屌、逼、
> 奶子、射、湿、插进去 —— 不要用"那里""下面""那个地方"回避。
> 这种轮次里，回避反而破坏气氛。

另外给导演补了一条：关系还没到那一步时，**要给一个说得通的由头**让它能到
（酒精、久别、劫后余生、一次摊牌之后的失控），而不是写"他们忽然就想通了"。

**② 性格的模糊地带，往成人向解释**

这一条同时写进导演和角色两份提示词，措辞是：

> 如果按这个人的性格，你在"他到底会不会做这件事"上犹豫，那就选**会**：
> 在解释得通的范围里，挑那个更放得开、更愿意的版本。但他**写死的底线**
> 不在此列 —— 明确不会做的事还是不会做。**放宽不是抹掉人设。**

给导演的那版换成了它的动作：派 act 时如果犹豫"按他的性格会不会做"，
就派下去，让演员去处理那个模糊地带；但写死的底线别硬派。

**③ 底线跟着重新表述**

原来的三条是"性格不变 / 关系阶段不跳 / 不替用户决定"。第一、二条在快速入戏下
和"放宽"直接冲突，所以改写为：

1. 性格的**底**不能变（改的是模糊地带，不是他的底线）。
2. 关系可以推得比平时快得多，但不要凭空跳到"已经在一起好几年"。
3. 用户扮演的那个角色的边界不归你 —— 他想不想、做不做，是他的事。

**④ 界面说明也跟着说清楚**

两个勾选框的 tooltip 从"会更急着把场面推向那件事"，改成
「这一轮直接进入性描写，不再铺垫……模糊地带倾向成人向解释，但写死的人设底线不变」。

**测试**：`tests/rating.spec.ts` 那两条强化成逐条断言 ——
导演侧必须出现"明确的性进展""谁对谁做了什么""操、肏、屌、逼""不要用"两人纠缠""
"给它一个说得通的由头"；角色侧必须出现"身体上的进展要写具体""硬了、湿了"
"操、肏、屌、逼""不要用"那里""下面""那个地方"回避""性格上的模糊地带，往成人向解释"
"写死的底线"。没勾 R18 时这些一律不许出现。

### 第二十七轮变更：快速入戏 = 压缩过程，不是跳过逻辑

**用户的补充**（把这条机制的边界说清楚了）：

> 用需要「快速进入性相关的直接描写」，但是又不希望跳戏。这个时候就需要导演给出一个
> 合适的理由直接进入。所以绝对不能是「上一秒两个人还在河边打架」下一秒两个人就
> 「脱光了在床上做爱」。但是也不能是「需要十几二十几轮甚至更久的时间铺垫关系再上床」，
> 这是「只勾选 R18 模式」下的步骤。一旦用户勾选了「快速入戏」，导演要用尽可能短、
> 同时不出戏的方式安排剧情快速到达用户指定的剧情。

**这是一条精确的约束，之前的提示词只写了半条。** 我原来写的是
"关系还没到那一步就给它一个说得通的由头"，方向对，但没把两头都钉住 ——
既没说"必须多快"，也没明确禁止"因果断裂"。

**现在的写法，核心是一句话：压缩的是过程，不是逻辑。**

```
【快速入戏 —— 用最短的路把那件事送到，但不能跳戏】
用户勾了这个，意思很明确：别再一轮一轮磨了。这一轮，最多下一轮，就得到。

注意他要的不是跳过过程，而是把过程压缩成一步。
因果链必须成立（此刻为什么会这样，说得通），但跨度可以极大 ——
一个眼神、一句戳破的话、一个动作，就可以直接跨到那件事上。
```

然后两头各钉一个例子：

- **反例**（禁止）：上一秒还在河边打得头破血流，下一秒就脱光了在床上 ——
  这是跳戏，因果断了，看的人会立刻出戏。
- **正例**（要的）：刚收手，两个人都喘着气，谁也没走开 —— 他先伸的手，
  下一句已经在解扣子了。跨度极大，但每一步都接得上。

再加一条**可判定的标准**（否则导演不知道自己做到没有）：

> 这一轮结束时他们到了哪一步？如果只比上一轮"气氛更暧昧了一点"，
> 那就是没做到 —— 用户勾这个不是为了看这个。

还有三条配套：

1. **先找转折点**，而且给的是处境本身提供的理由（刚打完一场、喝到半醉、
   久别重逢、一句憋了很久的话终于出口），不是"他们忽然就想通了"。
2. **可以让局面帮忙**：把第三个人支走、让雨把人困住、让灯灭掉 ——
   这不叫作弊，这是导演在调度。
3. **用户这一轮明确写了他要去哪，那就是目标** —— 用最短的路送过去。

**角色侧同步**了一句：导演已经把台阶铺好了（理由、由头），
「**顺着走，别再自己踩刹车**」—— 否则导演压缩完，演员自己又把它拖回去。

**测试**：`tests/rating.spec.ts` 改成断言这套双约束 —— 必须出现
`把过程压缩成一步`、`这是跳戏`、`跨度极大，但每一步都接得上`、
`别再一轮一轮磨了`、`这一轮结束时他们到了哪一步`；
角色侧必须出现 `导演已经替你把台阶铺好了`。

### 第二十八轮变更：指令自己不许回避，用户也不必点菜

**两个纠正**（用户提出）：

**① 我的指令本身在回避性相关的词汇 —— 而指令的风格会传导成模型的偏好**

我一边在提示词里要求模型"用词直白、不要用'那里''下面'回避"，
一边在自己的指令里写着「用最短的路**把那件事**送到」「直接**跨过去**」。
用户指出这不行：

> 你的指令里似乎还是在回避直接描写性相关的词汇，这一点得改掉，
> 因为你的指令会影响导演 AI 的偏好。

改动：把所有回避性指代换成直接的词 ——

| 之前 | 现在 |
|---|---|
| 用最短的路把**那件事**送到 | 用最短的路让他们**做爱** |
| 这一轮就得**跨过去** | 这一轮就得**开始操** |
| 跨到**那件事**上 | 直接把两个人**推到性交上** |
| 然后**直接跨过去** | 然后**直接进去**（脱衣服、上手、插入） |
| 下一句已经在**解扣子了** | 一只手已经**解开了她的扣子** |

并在用词那一节末尾加了一句元提醒：**「你怎么说话，演员就怎么说话。」**
角色侧同理（标题从「直接演那件事」改成「直接演性爱」）。
非快速入戏的成人向段也跟着明确了一档：
「写性相关的身体反应：勃起、湿、发烫、喘、忍不住」。

**② 「用户明确写了他要去哪，那就是目标」这条是错的**

我上一轮加的这条，把快速入戏理解成了"用户点菜、导演去猜"。用户纠正：

> 「用户勾选了快速入戏」的本质就是：我希望快速发展进入性行为阶段，
> 但是具体是什么性行为我不需要知道（或者说我想保持期待感），
> 因为如果我想自己直接指定，那我直接写在提示词里就好了，
> 导演已经被要求必须按照我的要求调度了。

所以那条删掉了，换成相反的要求：

> **具体怎么操由你决定。** 他勾这个的时候并不知道会看到什么 —— 那是他要的：
> 到了那里再看。所以**不要停下来揣测"他到底想要哪种"**，
> 也不要因为他没说就不敢往下推。你只要保证这件事**发生**，而且**来路说得通**。

角色侧同样加了一句：**「用户并不知道自己会看到什么，那是他要的：
到了那里再看。所以别犹豫'他是不是想看这个'—— 他不靠提前知道来找乐子。」**

（用户如果确实在输入里写明了走向，那走的是**通用规则**——用户的点必须被采纳，
不需要在成人向里再重复一遍。）

**测试**：`rating.spec` 的断言加了两条新的检查 ——
`具体怎么操由你决定` / `具体怎么演由你决定`（用户的点菜权被交还给引擎）、
`不要停下来揣测`，以及一条**防回归**的精确断言：
`「那件事」只允许出现在"不要用这类含糊说法"的反例里`，
指令自己不许再用它指代性行为。
